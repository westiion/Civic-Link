# Hybrid+Graph 확장 구현과 성능 분석

**목표**

- Hybrid 검색에 그래프 기반 근거 확장을 결합해 검색 성능 개선
- 기존 Hybrid와의 성능 비교 및 실패 분석을 통해 효과와 한계 확인

**설명 순서**

1. **확장 구조** — 검색 흐름과 주요 설정
2. **성능 비교** — 기존 Hybrid 대비 벤치마크 결과
3. **사례 분석** — 개선된 질문과 남은 실패 원인
4. **개선 가설** — 세 가설의 구현과 실험 결과
5. **후속 방향** — 남은 한계와 다음 개선 과제

<br>

## 1 왜 Hybrid에 그래프 확장을 붙였는가

Hybrid의 한계: 질문과 관련 있는 문서를 찾더라도, 답변에 함께 필요한 정의·위임 조항이나 다른 출처의 근거가 빠질 수 있다.
그래프 확장의 목적: 문서 간 명시적인 근거·참조 관계를 활용해, 텍스트 유사성만으로 놓치기 쉬운 근거를 보완한다.

<br>

## 2 확장 구현

### 2.1 검색 흐름

```text
사용자 질문
  ↓
BM25 + Dense를 결합한 Hybrid 검색
  ↓
Hybrid 후보 100개 확보
  ├─ 100개는 최종 결합 후보로 보관
  └─ 상위 10개 청크의 evidence 바인딩 조회
          ↓
      그 원문과 연결된 서비스·법 조항에서 시작 노드 최대 5개 선택
          ↓
      근거·참조·서류·기관·소속 법령의 다섯 관계를 정방향으로 최대 2단계 탐색
          ↓
      시작 노드와 탐색 경로에 연결된 원문 근거 수집
          ↓
      Graph 후보를 정렬해 최대 100개 유지
          ↓
Hybrid 후보와 Graph 후보를 청크 ID로 합치고 순위 결합
  ↓
최종 10개와 출처·탐색 경로 반환
```
<br>

### 2.2 검색 설정

동일한 조건에서 성능을 비교하기 위해 다음 설정을 사용했다.

**검색설정**

| 항목 | 설정 |
|---|---|
| Hybrid 후보 | 상위 100개 |
| 시작점 조회 범위 | Hybrid 상위 10청크 |
| 시작 노드 유형 | Service·Article |
| 시작점 선택 기준 | 검색 청크의 노드·관계 evidence 바인딩 |
| 시작 노드 수 | 최대 5개, 청크당 최대 2개 |
| 탐색 방향·깊이 | 정방향, 최대 2-hop |
| 탐색량 상한 | 노드 처리 1,000회·엣지 처리 5,000회 |
| Graph 후보 | 점수순 최대 100개 |
| 최종 반환 | 상위 10개 |

**탐색관계**

| 관계 | 연결 |
|---|---|
| `GROUNDED_BY` | 서비스 → 근거 조항 |
| `REFERENCES` | 조항 → 참조 조항 |
| `REQUIRES` | 서비스 → 제출서류 |
| `HANDLED_BY` | 서비스 → 처리기관 |
| `PART_OF` | 조항 → 소속 법령 |

### 2.3 후보 순위 결정
후보 순위는 Graph 내부 정렬 → Hybrid와 순위 결합의 두 단계로 결정한다.

| 요소 | 계산 방식 | 반영하려는 기준 |
|---|---|---|
| **시작점 가중치** | `1 / 시작 청크의 Hybrid 순위` | Hybrid가 높게 평가한 청크에서 출발한 근거를 우선 |
| **질문–청크 관련도** | 질문과 청크에 공통으로 등장하는 Kiwi 토큰의 IDF 가중치 비율 | 질문의 핵심 표현을 포함한 근거를 우선 |
| **탐색 거리** | `1 / (1 + 0.12 × hop)` | 시작점에서 멀어질수록 점수를 완만하게 낮춤 |

Graph 점수 = 시작점 가중치
           × (0.45 + 질문–청크 관련도)
           ÷ (1 + 0.12 × hop)
           × 근거 유형 보정

최종 점수 = 1 / (60 + Hybrid 순위)
          + 1 / (60 + Graph 순위)


한 목록에만 있는 청크는 그 목록의 점수만 받는다. 두 목록에 모두 있으면 두 점수를 받는다. BM25와 Dense를 합쳐 Hybrid를 만드는 첫 결합 뒤에, **Hybrid와 Graph를 합치는 두 번째 결합**이 있는 구조다.

<details>
<summary>정확한 Graph 점수식과 구현 파일</summary>

기본 시작점 가중치는 `1 / 시작 청크의 Hybrid 순위`다. Graph 점수는 이 가중치에 `(0.45 + Kiwi IDF 관련도) / (1 + 0.12 × hop)`을 곱하고, 조건 evidence에는 0.95를 추가로 곱한다. IDF 관련도는 질문의 토큰 중 corpus에서 드문 토큰에 더 큰 비중을 주는 겹침 점수다.

[hybrid_graph.py](../../scripts/hybrid_graph.py)가 시작점 선택·탐색·결합을 구현하고, [run_week4.py](../../scripts/run_week4.py)가 기본 확장과 가설별 조건을 실행한다. [compare_extension.py](../../scripts/compare_extension.py)는 비교 조건과 평가 결과를 확인한다.

</details>

### 3.2 질문 유형별 성능

각 칸은 Recall@10 · 완전 회수 질문 수를 나타낸다.

| 질문 유형 | 질문 수 | Hybrid | Hybrid+Graph |
|---|---:|---:|---:|
| 직접 질의 | 45 | 95.56% · 43/45 | 93.33% · 42/45 |
| 서비스 찾기 | 15 | 70.00% · 10/15 | **86.67% · 13/15** |
| 제출서류 | 19 | 89.47% · 17/19 | **92.11%** · 17/19 |
| 요건·조건 | 78 | 80.56% · 61/78 | 80.56% · **62/78** |
| 법적 근거 | 4 | 62.50% · 2/4 | 58.33% · 2/4 |
| 법령 상호참조 | 10 | 68.33% · 5/10 | 53.33% · 3/10 |
| 여러 출처·다단계 | 5 | 36.67% · 1/5 | **50.00% · 2/5** |
| 처리기관 | 1 | 100.00% · 1/1 | 100.00% · 1/1 |

- 개선
  - 서비스 찾기·여러 출처 질문에서 완전 회수 증가
- 부분 개선
  - 제출서류는 완전 회수 수가 같지만, 필요한 근거의 회수 비율 증가
- 악화
  - 법령 상호참조는 완전 회수 5→3개, Recall 68.33%→53.33%
  - 질문 수가 적은 유형은 개별 사례와 함께 해석해야 한다.

**결과해석**
- 질문과 개별 청크의 관련성’에 ‘같은 서비스에 연결된 근거’라는 정보를 더해 검색 결과를 보완했다. 
- 법령 관계를 활용하는 질문에서는 한계가 드러났다. 연결된 조항을 탐색하는 것뿐 아니라, 질문에 필요한 조항을 선택하고 최종 결과에 남기는 과정의 개선이 필요하다.

## 4 실패 단계와 대표 사례

### 4.1 어디에서 근거를 놓쳤는가
후보 확보와 최종 선택을 구분해 분석했다.
후보 Recall: Hybrid 상위 100개 97.65% → Graph 후보 결합 후 98.02%
최종 Recall@10: 기본 확장 82.77%

후보에는 필요한 근거가 대부분 포함됐지만, 최종 상위 10개를 선택하는 과정에서 상당수가 탈락했다.

| 실패 단계 | 질문 수 | 점검할 부분 |
|---|---:|---|
| 놓친 근거가 모두 후보 안에 있음 | **31** | 최종 순위 |
| 놓친 근거가 모두 후보 밖에 있음 | **3** | 시작점·근거 연결·탐색 범위 |
| 후보 누락과 순위 탈락이 함께 발생 | **1** | 후보 확보와 최종 선택 |
| **불완전 회수 합계** | **35** | |

근거 단위로도 누락된 45그룹 중 41그룹이 후보 안에 있었다. 우선 개선할 부분은 확보한 근거를 최종 결과에 남기는 순위 계산이다.

<br>

### 4.2 발견한 참조 근거가 최종 순위에서 탈락

대표 사례 — N040: 기초연금 대리 신청의 친족 범위

그래프는 시행규칙의 참조 관계를 따라 친족 범위를 정의한 민법 제777조를 찾았다.
필요한 근거	Hybrid 후보 순위	Graph 후보 순위	최종 순위
기초연금법 제10조	10	2	3
기초연금법 시행규칙 제6조	2	7	2
민법 제777조	후보 밖	9	42


- 발견: Hybrid가 놓친 민법 근거를 Graph가 추가 확보
- 탈락 원인: Graph에만 등장해 한쪽 순위의 점수만 받고, 두 목록에 공통으로 등장한 후보에 밀림
- 개선 방향: Graph에서 새로 찾은 필수 참조 근거가 최종 결과에 남도록 결합·재정렬 방식 검증
N050의 휴업사실증명 관련 참조 근거도 Graph 16위 → 최종 34위로 탈락했다.

Graph가 Hybrid 후보 밖에서 새로 확보한 정답 근거는 두 그룹이었지만, 둘 다 최종 10개에 포함되지 못했다.

<br>

### 4.3 같은 서비스의 근거라도 질문에 필요한 내용은 다름
성공 유지 — A029: 신분증 제출서류
“주민등록증과 운전면허증을 둘 다 가져가야 하나요?”

- 수집 경로: 서비스 → REQUIRES → 서류
- 결과: 정답 근거가 Hybrid 2위 → 최종 2위로 유지
- 해석: 기존 성공을 유지한 사례이며, 확장으로 새로 해결한 질문은 아님
남은 실패 — N057: 국세·지방세 납세증명의 법적 근거
- 관찰: HANDLED_BY 경로로 수집한 신청 절차 청크가 상위에 포함
- 결과: 질문에 필요한 지방세 근거 조항은 최종 12위로 탈락
- 개선 방향: 같은 서비스의 일반 안내와 질문이 요구하는 법적 근거를 구분해 정렬
분석에서 확인한 한계
- 서비스와 관련 있다는 이유만으로 질문에 필요한 근거가 되는 것은 아니다.
- 근거 청크를 찾았더라도, 답변에 사용하려면 본문의 조건·예외·대안·부정 표현까지 확인해야 한다.

<br>

## 5 개선 가설

실패 원인을 시작점 선택 → 근거 연결 → 최종 정렬로 나누고, 각 단계의 개선 효과를 검증하기 위해 세 가설을 설정했다.
| 가설 | 해결하려는 문제 | 검증 방법 |
|---|---|---|
| **H1. Hybrid 기반 시작점이 근거 도달에 유리하다** | 질문 표현과 노드 명칭의 차이로 적절한 시작점을 놓침 | **Kiwi 명칭 매칭**과 **Hybrid 검색 결과의 evidence 바인딩 기반 선택** 비교 |
| **H2. 누락된 evidence 연결을 보완하면 근거 회수가 개선된다** | 원문은 있지만 별칭·축약 표기·부정문 처리 문제로 그래프 연결이 누락됨 | 검수된 **evidence 바인딩 3건의 보완 전후** 비교 |
| **H3. 후보를 재정렬하면 필요한 근거가 최종 결과에 더 잘 남는다** | 정답 근거가 후보에 있어도 최종 10개에서 탈락함 | 동일 후보에서 **RRF**와 **청크·인용문 관련도를 추가한 규칙 기반 재정렬** 비교 |


실험 범위
- H1: Bigram이 아닌 현재 Kiwi 기반 명칭 매칭과 비교
- H2: 최신 법령 참조 처리는 유지하고, 확인된 바인딩 누락만 비교
- H3: 학습형 모델 없이 고정 규칙으로 재정렬
세 가설은 독립적인 비교 실험이며, H1→H2→H3를 순차적으로 누적한 결과가 아니다.

<br>

## 7 다음에는 무엇을 개선할 것인가

아래는 이번 결과에서 도출한 **후속 작업**이며 현재 구현·성능표에 포함된 방법과 구분한다.

### 우선순위 1 필요한 근거를 최종 순위에 남기기

**출발점:** N040·N050은 Graph가 새 참조 근거를 찾고도 잃는다. N029는 H3에서 비교 대상 한쪽을 잃고, N056은 연도별 고시·시행규칙을 둘 다 잃는다. H3 누락 43그룹 중 39그룹이 후보 안에 있다.

**구현 가설:** 같은 후보에서 질문과 원문을 함께 읽는 문맥 기반 reranker를 비교한다. 서비스·신청인·연도·발급 채널·부정 조건을 함께 확인하고, 여러 출처를 요구하는 질문은 필요한 각 출처가 남는지 점검한다. Graph에서만 찾은 정의·위임 근거에 대한 별도 보존 정책도 독립적으로 검증한다.

**연구 참고:** [Passage Re-ranking with BERT](https://arxiv.org/abs/1901.04085)는 질문 기반 passage 재정렬의 출발점이다. [RRF 원 논문](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf)은 순위 결합의 근거지만, 우리 데이터의 모든 질문에서 회귀가 없다는 보장은 아니다. 해당 학습형 reranker를 현재 구현한 것은 아니다.

**검증 기준:** Recall·완전 회수·MRR과 함께 Hybrid 성공 상실 수, Graph-only 정답 그룹의 최종 생존 수, 다른 서비스 유입, 추가 지연시간을 측정한다.

### 우선순위 2 시작점과 관계의 적합성을 함께 선택하기

**출발점:** N020의 시작점 편중과 N057의 절차 청크 유입이 남았다. 필요한 관계가 구현돼 있어도 질문에 맞는 시작점과 근거가 우선 선택되는 것은 아니다.

**구현 가설:** Hybrid 바인딩 후보와 Kiwi 서비스 후보를 함께 확보하고, 서비스·조문 시작점의 다양성을 보장한다. 모든 관계를 일괄적으로 같은 수준으로 취급하는 대신 질문과 관계의 적합성을 탐색·순위에 반영한다. 시작점 고정 여부와 관계별 추가 효과를 분리해 실험한다.

**연구 참고:** [BLINK](https://aclanthology.org/2020.emnlp-main.519/)의 후보 검색·문맥 재정렬은 시작점 선택의 참고다. [RoG](https://arxiv.org/abs/2310.01061)의 관계 경로 계획은 필요한 경로를 선택하는 연구 방향이다. 우리 서비스 그래프에 적용하는 것은 후속 가설이며 논문 구현을 이미 사용했다는 뜻은 아니다.

**검증 기준:** 실제 질문에서 시작점을 선택하고, 평가용 정답 유형·서비스 ID를 검색기에 넘기지 않는다. 같은 예산에서 적절한 시작점 포함→후보 회수→최종 회수를 나눠 측정한다.

### 우선순위 3 후보 밖 근거와 고시의 진입 경로 보완

**출발점:** N043·N052·B010·B011에는 후보 밖 근거가 남고, N056의 고시는 Law 노드 식별 evidence에만 연결된다. 원문이 없어서 생긴 문제와 구분해야 한다.

**구현 가설:** 공통 절차 조항의 적용 대상, 고시의 대상·연도·수치 기준을 원문으로 검수한 뒤 적절한 진입 경로를 추가한다. B010·B011처럼 진입 엣지가 없는 조항을 무조건 깊게 탐색하는 것으로 해결하려 하지 않는다.

**검증 기준:** 연결 정확성, 실제 선택된 시작점에서의 도달 가능성, 기존 결과의 회귀를 함께 확인한다. 노드·엣지 수 증가만으로 성능 개선을 주장하지 않는다.

### 다음 검증에서 고정할 원칙

- 같은 질문으로 피드백을 받으며 수정했으므로, [의도 묶음](../../data/intent_groups.jsonl)이 섞이지 않는 별도 고정 평가셋에서 일반화를 확인한다. 현재 결과에 대한 통계적 유의성은 아직 검증하지 않았다.
- 시작점·관계·가중치·재정렬 중 한 요인을 먼저 바꾼다. H1 균등 가중치와 H3의 조합 효과는 이번 독립 실험 결과를 더해 추정할 수 없다.
- Extension 자체의 0/1/2/3-hop 비교는 후속 과제다. 기존 Graph 단독의 hop 표를 Extension의 hop 실험으로 제시하지 않는다.
