# Hybrid+Graph 확장 구현과 성능 분석

**목표**

- Hybrid 검색에 그래프 기반 근거 확장을 결합해 검색 성능 개선
- 기존 Hybrid와의 성능 비교 및 실패 분석을 통해 효과와 한계 확인

**설명 순서**

1. **확장 구조** — 검색 흐름과 주요 설정
2. **성능 비교** — 기존 Hybrid 대비 벤치마크 결과
3. **사례 분석** — 개선된 질문과 남은 실패 원인
4. **개선 가설** — 세 가설의 구현과 실험 결과
5. **후속 방향** — 남은 한계와 다음 개선 과제


## 1 왜 Hybrid에 그래프 확장을 붙였는가

Hybrid의 한계: 질문과 관련 있는 문서를 찾더라도, 답변에 함께 필요한 정의·위임 조항이나 다른 출처의 근거가 빠질 수 있다.
그래프 확장의 목적: 문서 간 명시적인 근거·참조 관계를 활용해, 텍스트 유사성만으로 놓치기 쉬운 근거를 보완한다.


## 2 이번 확장을 어떻게 구현했는가

### 2.1 검색 흐름

```text
사용자 질문
  ↓
BM25 + Dense를 결합한 Hybrid 검색
  ↓
Hybrid 후보 100개 확보
  ├─ 100개는 최종 결합 후보로 보관
  └─ 상위 10개 청크의 evidence 바인딩 조회
          ↓
      그 원문과 연결된 서비스·법 조항에서 시작 노드 최대 5개 선택
          ↓
      근거·참조·서류·기관·소속 법령의 다섯 관계를 정방향으로 최대 2단계 탐색
          ↓
      시작 노드와 탐색 경로에 연결된 원문 근거 수집
          ↓
      Graph 후보를 정렬해 최대 100개 유지
          ↓
Hybrid 후보와 Graph 후보를 청크 ID로 합치고 순위 결합
  ↓
최종 10개와 출처·탐색 경로 반환
```

### 2.2 설정값과 각 설정이 맡는 역할

시작점·탐색 예산·점수와 허용 관계를 아래와 같이 설정했다. ‘역할’은 현재 코드에서 그 설정이 어떤 제한과 동작을 만드는지 설명한 것이다. **10개·5개·2-hop·100개가 최적값이라고 검증한 것은 아니다.**

| 정한 항목 | 현재 설정 | 역할과 고려한 한계 |
|---|---|---|
| 시작점으로 볼 문서 범위 | Hybrid 상위 10청크 | 상위 문서에 진입 범위를 좁힌다. 필요한 선행 조문이 36위라면 시작점 선정에서 빠질 수 있다 |
| 전체 결합용 Hybrid 후보 | 상위 100청크 유지 | 그래프 탐색과 별개로 기존 검색 후보를 보존한다 |
| 시작점으로 인정할 연결 | 서비스·조항의 안내/본문 evidence, 또는 허용된 관계의 출발 노드 evidence | 텍스트가 비슷하다는 이유만으로 연결하지 않고, 저장된 원문 바인딩으로 진입한다 |
| 시작 노드 수 | 전체 최대 5개, 한 청크당 최대 2개 | 탐색량을 제한하고 한 청크에 시작점이 전부 몰리는 것을 막는다. 같은 청크의 노드 간 선택은 아직 ID 순서다 |
| 탐색 관계 | `GROUNDED_BY`, `REFERENCES`, `REQUIRES`, `HANDLED_BY`, `PART_OF` | 근거 조항·참조 조항·제출서류·기관·소속 법령으로 확장한다 |
| 탐색 방향·깊이 | 정방향, 최대 2-hop | 서비스에서 근거 조항을 거쳐 참조 조항까지 도달할 수 있는 범위다 |
| 탐색량 상한 | 노드 처리 1,000회, 엣지 처리 5,000회 | 연결이 많은 곳에서 탐색량이 지나치게 커지는 것을 제한한다 |
| Graph 후보 수 | 점수순 최대 100개 | 탐색에서 나온 모든 근거를 최종 정렬에 넣지 않고 후보 수를 제한한다 |
| 최종 반환 | 상위 10개 | 기존 검색과 같은 반환 수로 비교한다 |

`GROUNDED_BY`는 서비스→근거 조항, `REFERENCES`는 조항→참조 조항, `REQUIRES`는 서비스→서류, `HANDLED_BY`는 서비스→기관, `PART_OF`는 조항→소속 법령이다. 시작점 유형은 여전히 Service·Article이다. 허용 관계 목록은 시작점 바인딩 역조회와 탐색 양쪽에 적용된다. 관계를 따라 이동하는 한 단계를 1-hop이라고 한다. 이동하지 않고 시작 노드에 붙은 evidence를 수집하는 경우는 0-hop이다.

### 2.3 후보의 순위는 어떻게 결정하는가

**Graph 안에서는** 시작점이 나온 Hybrid 순위, 질문과 청크의 Kiwi 토큰 관련도, 이동한 hop 수로 후보를 정렬한다. 구조만 보고 순위를 정하는 방식은 아니다. BM25와 Graph의 관련도 계산에는 현재 Kiwi 토큰화를 사용하고, Dense는 임베딩 모델 자체의 처리를 사용한다.

**마지막에는** 두 순위 목록을 RRF로 합친다. RRF는 서로 다른 검색 점수의 크기 대신 **몇 위에 나왔는지**를 이용하는 결합 방식이다.

```text
최종 점수 = 1 / (60 + Hybrid 순위)
          + 1 / (60 + Graph 순위)
```

한 목록에만 있는 청크는 그 목록의 점수만 받는다. 두 목록에 모두 있으면 두 점수를 받는다. BM25와 Dense를 합쳐 Hybrid를 만드는 첫 결합 뒤에, **Hybrid와 Graph를 합치는 두 번째 결합**이 있는 구조다.

<details>
<summary>정확한 Graph 점수식과 구현 파일</summary>

기본 시작점 가중치는 `1 / 시작 청크의 Hybrid 순위`다. Graph 점수는 이 가중치에 `(0.45 + Kiwi IDF 관련도) / (1 + 0.12 × hop)`을 곱하고, 조건 evidence에는 0.95를 추가로 곱한다. IDF 관련도는 질문의 토큰 중 corpus에서 드문 토큰에 더 큰 비중을 주는 겹침 점수다.

[hybrid_graph.py](../../scripts/hybrid_graph.py)가 시작점 선택·탐색·결합을 구현하고, [run_week4.py](../../scripts/run_week4.py)가 기본 확장과 가설별 조건을 실행한다. [compare_extension.py](../../scripts/compare_extension.py)는 비교 조건과 평가 결과를 확인한다.

</details>

## 3 실제 성능은 어떻게 달라졌는가

### 3.1 기본 Hybrid와 기본 확장의 결과

같은 corpus와 질문에서 **기존 Hybrid의 상위 10개**와 **확장의 상위 10개**를 비교했다. 전체 204질문 중 근거가 정해진 177질문을 평가하고, 추가 확인·응답 보류가 필요한 27질문은 진단용으로 분리했다.

질문에 필요한 근거가 세 종류라면 모두 찾아야 **완전 회수**다. **Recall@10**은 필요한 근거 중 찾은 비율을 질문마다 계산한 평균, **MRR@10**은 첫 정답 근거가 얼마나 앞에 나오는지를 나타낸다. 답변 생성 정확도를 평가한 수치는 아니다.

| 검색 방식 | 완전 회수 / 177 | Recall@10 | MRR@10 |
|---|---:|---:|---:|
| 기존 Hybrid | 140 | 82.20% | 0.6061 |
| 기본 Hybrid+Graph | 142 | 82.77% | 0.6118 |

**기본 확장은 Hybrid보다 완전 회수 2문항, Recall 0.56%p 높았다.** 근거 회수량은 9문항에서 늘고 6문항에서 줄었으며, 1문항은 같은 개수의 다른 근거를 찾았다. 완전 회수 기준으로는 새 성공 7개와 기존 성공 상실 5개가 동시에 발생했다. 평균 개선과 개별 회귀를 함께 봐야 한다.

<details>
<summary>BM25·Dense·Graph 단독을 포함한 전체 벤치마크</summary>

| 검색 방식 | 완전 회수 / 177 | Recall@10 | MRR@10 |
|---|---:|---:|---:|
| BM25 | 128 | 75.61% | 0.5358 |
| Dense | 126 | 75.52% | 0.4987 |

| Graph 단독 0-hop | 78 | 46.80% | 0.3747 |
| Graph 단독 1-hop | 108 | 62.81% | 0.4650 |

| Graph 단독 3-hop | 105 | 61.68% | 0.4636 |

Graph 단독과 Hybrid+Graph는 시작점을 찾는 방식과 최종 후보 결합 방식이 다르다. 이번 과제에서는 Hybrid에 확장을 붙였을 때의 추가 효과를 확인한다.

### 3.2 어떤 질문에서 좋아지고 나빠졌는가

각 칸은 **Recall@10 (완전 회수 질문 수)**다. 유형별 분모가 작을 수 있으므로 질문 수도 함께 표시한다. H3는 뒤에서 설명할 최종 재정렬 조건이다.


| 질문 유형 | 질문 수 | Hybrid | 기본 확장 | H3 재정렬 |
|---|---:|---:|---:|---:|
| 직접 질의 | 45 | 95.56% (43/45) | 93.33% (42/45) | 93.33% (42/45) |
| 서비스 찾기 | 15 | 70.00% (10/15) | 86.67% (13/15) | 83.33% (12/15) |
| 제출서류 | 19 | 89.47% (17/19) | 92.11% (17/19) | 97.37% (18/19) |
| 요건·조건 | 78 | 80.56% (61/78) | 80.56% (62/78) | 82.26% (63/78) |
| 법적 근거 | 4 | 62.50% (2/4) | 58.33% (2/4) | 58.33% (2/4) |
| 법령 상호참조 | 10 | 68.33% (5/10) | 53.33% (3/10) | 53.33% (3/10) |
| 여러 출처·다단계 | 5 | 36.67% (1/5) | 50.00% (2/5) | 50.00% (2/5) |
| 처리기관 | 1 | 100.00% (1/1) | 100.00% (1/1) | 100.00% (1/1) |

- **제출서류는 완전 회수 17/19를 유지하면서 Recall이 89.47%→92.11%로 높아졌다.** H3에서는 만료 여권 질문도 회복해 완전 회수 18/19가 됐다.
- **서비스 찾기와 여러 출처 질문은 Hybrid 대비 회수에 도움이 됐다.** 서비스에 묶인 근거를 함께 가져오는 효과가 있다.
- **법령 상호참조는 여전히 Hybrid보다 낮다.** 관련 조항을 찾아도 최종 순위에서 탈락하는 사례가 남았다. 처리기관은 1문항뿐이므로 일반화하기 어렵다.

**개선 사례 — [SJ-A-003](QUESTION_TRACES.md#sj-a-003):** 정부24 유료 안내와 성남시 무인발급 무료 안내를 비교하는 질문이다. Hybrid는 세 근거 중 하나만 찾았지만 기본 확장·H3는 모두 찾았다. 근거 순위는 Hybrid 84·5·18위→기본 확장 4·2·3위다. 세 근거의 대표 경로가 모두 서비스의 0-hop evidence이므로, 여러 관계를 이동한 성과보다 **서비스에 다른 출처의 근거를 묶어 둔 효과**로 해석한다.


## 4 개선된 사례와 여전히 실패하는 지점

### 4.1 후보를 못 찾은 문제와 찾고도 밀린 문제

Hybrid 후보 100개의 Recall은 97.65%, Graph와 합친 후보 Recall은 98.02%다. 기본 확장과 H3가 쓰는 후보 풀은 같다. 따라서 H3의 개선은 새로운 문서를 찾은 효과가 아니라 **이미 찾은 근거의 최종 순위를 바꾼 효과**다.

| 불완전 회수 질문의 실패 단계 | 기본 확장 | H3 | 우선 점검 대상 |
|---|---:|---:|---|
| 누락 근거가 모두 후보 안에 있음 | 31 | 30 | 최종 순위·대상 및 조건 구분 |
| 누락 근거가 모두 후보 밖에 있음 | 3 | 3 | 시작점·바인딩·관계·탐색 범위 |
| 두 문제가 함께 있음 | 1 | 1 | 후보 확보와 최종 선택 양쪽 |
| 합계 | 35 | 34 | 성공 수와 별개로 남은 실패를 분해 |

근거 그룹 단위로 기본 확장은 **45개 누락 중 41개가 후보 안**, H3는 **43개 중 39개가 후보 안**이다. 후보 밖 근거는 두 조건 모두 4그룹이다. 모든 평가 질문에 시작점이 있었고 탐색 한도 초과는 없었지만, 시작점이 있다는 것과 적절한 시작점이라는 것은 다르다.

### 4.2 참조 조항을 찾았어도 최종 결과에서 밀린다

**[SJ-N-040](QUESTION_TRACES.md#sj-n-040): “기초연금을 친척이 대신 신청할 수 있는 범위”**

그래프는 기초연금법 시행규칙에서 친족 범위를 정의한 민법 제777조까지 REFERENCES로 도달한다. 그러나 민법 근거는 Hybrid 상위 100개 밖에 있어 Graph 쪽 RRF 점수만 받는다.

| 필요한 근거 | Hybrid 100내 | Graph 내부 | 기본 결합 | H3 |
|---|---:|---:|---:|---:|
| 기초연금법 제10조 | 10 | 2 | 3 | 3 |
| 기초연금법 시행규칙 제6조 | 2 | 7 | 2 | 2 |
| 민법 제777조 | 없음 | 9 | 42 | 49 |

민법 근거는 Graph 9위여서 RRF 점수가 `1/(60+9)` 한 항만 생긴다. 두 목록에 함께 나타나는 주변 조항은 두 항의 합을 얻는다. **새 근거 발견에는 성공했지만 최종 선택에는 실패**한 사례다. 현재 규칙 재정렬도 이를 회복하지 못했다.

[SJ-N-050](QUESTION_TRACES.md#sj-n-050)의 휴업사실증명→국세청 규정→민원 처리법 시행령 경로도 새 근거가 Graph 16위→기본 34위→H3 43위로 밀렸다. Hybrid 100개 밖에서 추가한 정답 그룹은 N040·N050의 두 그룹이며, 둘 다 최종 10개에 남지 못했다.

### 4.3 제출서류 근거의 활용과 질문에 맞지 않는 후보의 경쟁

**성공 유지 — [SJ-A-029](QUESTION_TRACES.md#sj-a-029):** 주민등록증과 운전면허증을 둘 다 가져가야 하는지 묻는다. 제출서류 근거는 Hybrid 2위이며, 확장에서 `서비스 → REQUIRES → 서류`로 수집돼 Graph 3위·최종 2위다. 그래프가 기존 성공 근거를 함께 지지한 사례이며, Hybrid 대비 새로 성공한 사례로 세지 않는다.

**남은 실패 — [SJ-N-057](QUESTION_TRACES.md#sj-n-057):** 국세·지방세 납세증명의 각각의 법적 근거를 묻는다. 현재 확장에서 HANDLED_BY 경로의 신청 절차 청크가 상위에 포함되지만, 필요한 지방세 근거 조항은 최종 12위로 빠진다. H3도 완전 회수를 회복하지 못했다. 질문에 필요한 근거 조항과 같은 서비스의 일반 안내를 구분하는 순위 계산이 필요하다.

기관·서류 연결이 정답 청크 회수에 도움을 주더라도, 짧은 엣지 인용 자체가 질문의 조건을 입증하는 것은 아니다. 법정대리인 질문의 경로 인용이 “위임장 제출”인 경우처럼, **청크 전체의 예외·대안·부정문을 읽어야 하는 사례**가 남아 있다.


## 5 왜 개선 가설을 세 가지로 나눴는가

세 가설은 **그래프 검색 과정의 서로 다른 실패 지점**에 대응한다. 여기서 H는 Hypothesis, 즉 검증할 가설을 뜻한다.

```text
H1 시작점을 잘 골랐는가?
      ↓
H2 필요한 근거에 실제로 연결돼 있는가?
      ↓
H3 모은 근거 중 정답을 최종 결과에 남겼는가?
```

시작점을 잘못 고르면 올바른 그래프가 있어도 다른 곳을 탐색한다. 시작점이 맞아도 연결이 없으면 근거를 모으지 못한다. 두 단계가 잘 작동해도 순위가 낮으면 최종 10개에서 빠진다. **어느 단계의 변경이 어떤 효과를 냈는지 알아보기 위해 세 문제를 분리한 것이다.**

| 가설 | 검증하려는 생각 | 이 가설이 필요한 이유 | 바꾸는 것 |
|---|---|---|---|
| **H1 시작점 선택 개선** | 노드 명칭만 맞추기보다 Hybrid가 찾은 원문의 문맥으로 진입하면 필요한 근거에 더 잘 도달한다 | 구어체 질문의 표현과 서비스·조문 이름이 달라 명칭 매칭이 실패할 수 있음 | 시작 노드 선정 방식 |
| **H2 관계·evidence 연결 보완** | 누락된 연결을 복구하면 기존 원문의 필요한 근거가 그래프 후보에 포함된다 | 원문은 corpus에 있어도 명칭·별칭·부정문 처리 때문에 그래프에 제대로 연결되지 않을 수 있음 | 그래프의 보완 대상 연결 |
| **H3 최종 재정렬** | 후보에 이미 있는 정답을 질문과의 관련도로 다시 평가하면 최종 결과에 더 잘 남는다 | 후보 Recall은 높지만 최종 Recall이 낮고, 새 참조 근거도 순위에서 탈락함 | 후보를 최종 정렬하는 방식 |


### 원래 구상과 이번 병합 코드의 차이

| 항목 | Notion의 구상 | 이번에 실제로 검증한 범위 |
|---|---|---|
| H1의 명칭 매칭 | Bigram 기반 시작점과 Hybrid 기반 시작점 비교 | 기존 피드백을 유지해 **Kiwi 명칭 매칭과 Hybrid 기반 시작점**을 비교 |
| H2의 연결 보완 | 누락된 관계·evidence 전반의 보완 | 최신 법령 참조 처리는 유지하고, **검수된 별칭·부정문 3건의 evidence 바인딩**만 전후 비교 |
| H3의 reranker | 같은 후보에서 RRF와 재정렬 비교 | 새 학습 모델 대신 **RRF·청크·인용문의 관련도를 합치는 규칙 기반 재정렬** 사용 |

따라서 이번 H1을 “Bigram보다 Hybrid가 좋았다”, H2를 “모든 법령 연결 누락을 해결했다”, H3를 “학습형 reranker를 검증했다”고 설명하면 실제 실험과 달라진다.

## 6 세 가설을 검증했더니 무엇이 달라졌는가

### 6.1 H1 시작점 선택 개선

**바꾼 것:** Kiwi로 질문과 노드 이름을 맞추는 방식에서 Hybrid 청크의 evidence 바인딩으로 시작점을 찾는 방식으로 바꿨다. 두 조건은 같은 적격 Service·Article 집합을 사용한다.

**고정한 것:** 그래프·다섯 관계·탐색 예산·후속 점수·RRF를 유지하고, 시작점 가중치는 두 조건 모두 **1**로 고정했다. 명칭 매칭 점수와 Hybrid 순위 점수의 차이까지 섞지 않기 위해서다.

| 지표 | 이전 조건 | 이후 조건 |
|---|---:|---:|
| 완전 회수 질문 | 127/177 | 143/177 |
| Recall@10 | 75.14% | 83.43% |
| Graph 후보 Recall | 67.89% | 83.33% |
| Hybrid+Graph 후보 Recall | 97.83% | 98.02% |
| MRR@10 | 0.5365 | 0.6088 |

근거 회수량이 늘어난 질문은 **27개**, 줄어든 질문은 **10개**다. Hybrid 원문을 통한 진입은 평균적으로 유리했지만 모든 질문에서 우월하지 않았다.

- **개선 [SJ-A-061](QUESTION_TRACES.md#sj-a-061):** 생계급여 통지 기한 조항은 명칭 시작점에서 결합 18위였지만 Hybrid 시작점에서는 7위로 올라왔다. 필요한 조항에 연결되는 시작점을 포함했다.
- **악화 [SJ-N-020](QUESTION_TRACES.md#sj-n-020):** 두 지방세 증명 서비스의 차이를 묻는다. 명칭 방식은 정답을 6·4위에 올렸지만 Hybrid 방식은 체납 조문으로 시작점이 쏠려 39·24위로 밀렸다. 서로 다른 서비스 근거를 보존할 시작점 다양성이 필요하다.

### 6.2 H2 누락 evidence 연결 보완

**바꾼 것:** 가족관계 등 축약 표기, 토지이용계획확인서/확인원 별칭, 국문 장애인증명의 “구비서류 없음” 세 evidence의 바인딩을 보완했다.

**고정한 것:** corpus·질문·다섯 관계·검색 설정·최신 법령 참조 파서를 유지했다. 노드 6,182개·엣지 9,437개는 같고, evidence record 11,095→11,098 및 서비스 바인딩 6개 추가만 비교했다. 새로운 법령을 수집한 실험이 아니다.

| 지표 | 이전 조건 | 이후 조건 |
|---|---:|---:|
| 완전 회수 질문 | 139/177 | 142/177 |
| Recall@10 | 81.36% | 82.77% |
| Graph 후보 Recall | 81.92% | 83.33% |
| Hybrid+Graph 후보 Recall | 98.02% | 98.02% |
| MRR@10 | 0.6039 | 0.6118 |

| 보완 대상 | 질문 | 보완 전→후의 핵심 근거 순위 | 결과 |
|---|---|---:|---|
| 가족관계 등 축약 표기 | [SJ-A-080](QUESTION_TRACES.md#sj-a-080) | 11→1 | Top-10 미회수→완전 회수 |
| 확인서/확인원 별칭 | [SJ-B-035](QUESTION_TRACES.md#sj-b-035) | 15→2 | Top-10 미회수→완전 회수 |
| 국문 증명의 구비서류 없음 | [SJ-B-038](QUESTION_TRACES.md#sj-b-038) | 11→1 | 부분→성공 |

이번 H2 실험에서는 **세 질문 모두 완전 회수로 바뀌었고 회수량 악화는 없었다.** 별칭·축약 표기·부정문을 원문 근거와 연결한 보완의 효과다.

바인딩 보완은 진입점에도 영향을 준다. A080은 관련 Service가 시작점에 추가됐고, B035는 같은 시작점에서 수집 근거가 늘었다. B038은 같은 Service가 더 이른 Hybrid 청크에서 선택돼 시작점 순서·가중치도 바뀌었다. 고정된 시작점에서 evidence 수집만 늘린 실험으로 해석하지 않는다.

전체 후보 Recall은 98.02%로 같았다. 필요한 원문이 이미 Hybrid 후보에 있었고, 바인딩 보완 후 Graph에서도 점수를 받을 수 있게 됐다. 원문 수집 확대의 효과와 구분한다.

### 6.3 H3 최종 재정렬

**바꾼 것:** RRF로 만든 순위에 질문과 청크·인용문의 관련도를 더해 최종 10개를 다시 정렬했다.

```text
재정렬 점수 = 0.5 × 정규화 RRF
            + 0.3 × 질문–청크 Kiwi IDF 관련도
            + 0.2 × 질문–인용문 Kiwi IDF 관련도
```

**고정한 것:** 시작점·탐색 경로·실제 후보 집합·최종 반환 수. 학습형 reranker가 아니라 고정 규칙이며, 0.5·0.3·0.2가 최적이라고 검증한 것은 아니다.

| 지표 | 이전 조건 | 이후 조건 |
|---|---:|---:|
| 완전 회수 질문 | 142/177 | 143/177 |
| Recall@10 | 82.77% | 83.80% |
| Graph 후보 Recall | 83.33% | 83.33% |
| Hybrid+Graph 후보 Recall | 98.02% | 98.02% |
| MRR@10 | 0.6118 | 0.6265 |

근거 회수량은 **3문항에서 개선, 1문항에서 악화**됐다.

| 질문 | 핵심 변화 | 해석 |
|---|---|---|
| [SJ-A-002](QUESTION_TRACES.md#sj-a-002) 만료 여권 | 33→6위, Top-10 미회수→완전 회수 | 후보에 있던 신분증 유효기간 근거를 올림 |
| [SJ-B-022](QUESTION_TRACES.md#sj-b-022) 부부의 기초연금 지급계좌 | 12→5위, Top-10 미회수→완전 회수 | 기본 확장이 잃었던 Hybrid 성공을 회복 |
| [SJ-N-039](QUESTION_TRACES.md#sj-n-039) 긴급생계지원의 자격·재산 조건 | 한 근거 13→10위, 1/3→2/3 | 개선됐지만 **여전히 부분 회수** |
| [SJ-N-029](QUESTION_TRACES.md#sj-n-029) 면세사업자 수입금액·과세표준 증명 비교 | 한 근거 8→12위, 성공→부분 | 비교할 두 서비스 중 한 근거를 잃음 |

N029에서는 주변 법 조항이 상위에 들어오면서 필요한 두 번째 서비스 근거가 8→12위로 밀렸다. 대상 서비스와 질문 조건을 함께 판단하는 재정렬이 다음 과제다.

### 6.4 가설별 개선과 최종 목표 달성을 구분

세 가설은 **각각의 통제 실험**이다. H1→H2→H3를 차례로 누적한 최종 모델을 평가한 것이 아니다. 기본 확장은 이미 H2 보완을 포함하고, H1은 시작점 가중치가 기본 확장과 다르다.

| 검색 방식 | 완전 회수 / 177 | Recall@10 | MRR@10 |
|---|---:|---:|---:|
| 기존 Hybrid | 140 | 82.20% | 0.6061 |
| 기본 확장 · 시작 청크 순위 가중치 | 142 | 82.77% | 0.6118 |
| H1 Hybrid 시작점 · 균등 가중치 | 143 | 83.43% | 0.6088 |
| H3 기본 확장 · 규칙 재정렬 | 143 | 83.80% | 0.6265 |

**이번 실행에서는 H3가 Recall·MRR이 가장 높고, 완전 회수 수는 H1과 동률**이다. Hybrid 대비 완전 회수 +3문항·Recall +1.60%p다. H3 기준 새 성공 7개와 기존 성공 상실 4개가 함께 발생했으며, 근거 회수량 기준으로는 10개 개선·5개 악화다. 개선 수치만 보고 회귀 사례를 숨기지 않는다.


## 7 다음에는 무엇을 개선할 것인가

아래는 이번 결과에서 도출한 **후속 작업**이며 현재 구현·성능표에 포함된 방법과 구분한다.

### 우선순위 1 필요한 근거를 최종 순위에 남기기

**출발점:** N040·N050은 Graph가 새 참조 근거를 찾고도 잃는다. N029는 H3에서 비교 대상 한쪽을 잃고, N056은 연도별 고시·시행규칙을 둘 다 잃는다. H3 누락 43그룹 중 39그룹이 후보 안에 있다.

**구현 가설:** 같은 후보에서 질문과 원문을 함께 읽는 문맥 기반 reranker를 비교한다. 서비스·신청인·연도·발급 채널·부정 조건을 함께 확인하고, 여러 출처를 요구하는 질문은 필요한 각 출처가 남는지 점검한다. Graph에서만 찾은 정의·위임 근거에 대한 별도 보존 정책도 독립적으로 검증한다.

**연구 참고:** [Passage Re-ranking with BERT](https://arxiv.org/abs/1901.04085)는 질문 기반 passage 재정렬의 출발점이다. [RRF 원 논문](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf)은 순위 결합의 근거지만, 우리 데이터의 모든 질문에서 회귀가 없다는 보장은 아니다. 해당 학습형 reranker를 현재 구현한 것은 아니다.

**검증 기준:** Recall·완전 회수·MRR과 함께 Hybrid 성공 상실 수, Graph-only 정답 그룹의 최종 생존 수, 다른 서비스 유입, 추가 지연시간을 측정한다.

### 우선순위 2 시작점과 관계의 적합성을 함께 선택하기

**출발점:** N020의 시작점 편중과 N057의 절차 청크 유입이 남았다. 필요한 관계가 구현돼 있어도 질문에 맞는 시작점과 근거가 우선 선택되는 것은 아니다.

**구현 가설:** Hybrid 바인딩 후보와 Kiwi 서비스 후보를 함께 확보하고, 서비스·조문 시작점의 다양성을 보장한다. 모든 관계를 일괄적으로 같은 수준으로 취급하는 대신 질문과 관계의 적합성을 탐색·순위에 반영한다. 시작점 고정 여부와 관계별 추가 효과를 분리해 실험한다.

**연구 참고:** [BLINK](https://aclanthology.org/2020.emnlp-main.519/)의 후보 검색·문맥 재정렬은 시작점 선택의 참고다. [RoG](https://arxiv.org/abs/2310.01061)의 관계 경로 계획은 필요한 경로를 선택하는 연구 방향이다. 우리 서비스 그래프에 적용하는 것은 후속 가설이며 논문 구현을 이미 사용했다는 뜻은 아니다.

**검증 기준:** 실제 질문에서 시작점을 선택하고, 평가용 정답 유형·서비스 ID를 검색기에 넘기지 않는다. 같은 예산에서 적절한 시작점 포함→후보 회수→최종 회수를 나눠 측정한다.

### 우선순위 3 후보 밖 근거와 고시의 진입 경로 보완

**출발점:** N043·N052·B010·B011에는 후보 밖 근거가 남고, N056의 고시는 Law 노드 식별 evidence에만 연결된다. 원문이 없어서 생긴 문제와 구분해야 한다.

**구현 가설:** 공통 절차 조항의 적용 대상, 고시의 대상·연도·수치 기준을 원문으로 검수한 뒤 적절한 진입 경로를 추가한다. B010·B011처럼 진입 엣지가 없는 조항을 무조건 깊게 탐색하는 것으로 해결하려 하지 않는다.

**검증 기준:** 연결 정확성, 실제 선택된 시작점에서의 도달 가능성, 기존 결과의 회귀를 함께 확인한다. 노드·엣지 수 증가만으로 성능 개선을 주장하지 않는다.

### 다음 검증에서 고정할 원칙

- 같은 질문으로 피드백을 받으며 수정했으므로, [의도 묶음](../../data/intent_groups.jsonl)이 섞이지 않는 별도 고정 평가셋에서 일반화를 확인한다. 현재 결과에 대한 통계적 유의성은 아직 검증하지 않았다.
- 시작점·관계·가중치·재정렬 중 한 요인을 먼저 바꾼다. H1 균등 가중치와 H3의 조합 효과는 이번 독립 실험 결과를 더해 추정할 수 없다.
- Extension 자체의 0/1/2/3-hop 비교는 후속 과제다. 기존 Graph 단독의 hop 표를 Extension의 hop 실험으로 제시하지 않는다.

## 8 이번 결과를 어떻게 정리할 수 있는가

**구현:** Hybrid가 찾은 원문에서 Service·Article 시작점을 찾고, 다섯 관계로 근거를 수집해 기존 후보와 결합하며 출처·경로를 남긴다.

**성능:** 기본 확장은 Hybrid의 140/177·Recall 82.20%에서 142/177·82.77%로 소폭 개선됐다. H3는 143/177·83.80%로 추가 개선했다. 다만 기존 성공을 잃은 질문도 있어 평균 성능과 회귀 사례를 함께 평가해야 한다.

**남은 문제:** 새로운 참조 근거가 최종 순위에서 탈락하고, 비교 질문의 한쪽 근거를 잃는 사례가 남는다. 다음 단계는 원문을 무조건 더 모으거나 탐색을 깊게 하는 것보다 **후보에 이미 있는 근거를 질문의 대상·조건에 맞게 남기는 것**이다.

P95는 저장된 204개 query latency를 정렬해 floor((n−1)×0.95) 위치로 계산했다. 확장 시간은 Hybrid 검색이 끝난 **후의 추가 처리**만 포함하며 인덱스 구성·그래프 로딩·파일 저장은 포함하지 않는다. 회사 API 호출은 캐시로 생략됐다. 따라서 위 표로 실제 온라인 전체 지연시간이나 GPU 추론 속도를 비교할 수 없다.

</details>

<details>
<summary>평가 한계와 수치 검증</summary>

평가 대상 177질문에 필수 근거 그룹 220개가 있다. 각 그룹은 허용 청크 중 하나를 찾으면 회수로 인정한다. Recall은 질문별 비율의 평균이므로 전체 회수 그룹의 단순 합산 비율과 다르다. 청크 회수 성공은 답변 생성 성공이나 인용문이 정답 명제를 직접 입증했다는 뜻이 아니다. Gold의 전수 사람 검수 상태도 아직 `pending`이다.

이번 실행의 저장된 14개 조건 지표를 다시 계산해 원 지표와 대조했다. 공유 Week3의 7종도 현재 Gold로 재평가해 저장된 Top-10 지표와 대조했다. 직전 실행과 이번 실행의 기존 7종 예측 JSON 내용은 동일하다. 보고서를 고치면서 검색이나 모델을 다시 실행하지 않았다.

**Notion은 설계 의도와 가설 정의의 출처로, 현재 실행 파일은 이번 성능 수치의 출처로 구분했다.** 이번 기본 비교는 Hybrid 140개→기본 확장 142개 완전 회수다. 원문에는 특정 설정값이 최적이라는 검증이나 세 가설을 누적한 최종 실험은 제시되어 있지 않다.
