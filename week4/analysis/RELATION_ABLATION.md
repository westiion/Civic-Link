# 관계 2개 → 5개 확장: 구현 및 성능 비교

> 이 문서는 `20261027_052016` 입력으로 수행한 관계 2개→5개 비교 기록입니다. 최신 `20261027_091116`의 H1·H2·H3 전체 결과는 [REPORT.md](REPORT.md), 전체 질문 분석은 [QUESTION_TRACES.md](QUESTION_TRACES.md)를 확인하세요.

다섯 관계를 모두 허용하자 전체 근거 회수 질문이 **132/177 → 142/177**, Recall@10이 **77.97% → 82.77%**로 개선됐다. Hybrid 단독의 140/177·82.20%도 소폭 넘어섰다. 가장 큰 변화는 제출서류 질문의 회복이었다. 다만 법적 근거 질문 하나는 주변 행정 안내가 올라오면서 악화됐다.

## 1. 무엇을 바꿨나

기존 그래프에는 이미 다섯 관계가 있었다. 그래프를 다시 만들거나 원문을 추가 수집하지 않고, Extension이 허용하는 관계 목록을 바꿨다.

| 관계 | 2개 조건 | 5개 조건 | 역할 |
|---|---|---|---|
| GROUNDED_BY | 사용 | 사용 | 서비스 → 근거 조항 |
| REFERENCES | 사용 | 사용 | 조항 → 참조 조항 |
| REQUIRES | 제외 | 사용 | 서비스 → 제출서류 |
| HANDLED_BY | 제외 | 사용 | 서비스 → 처리기관 |
| PART_OF | 제외 | 사용 | 조항 → 소속 법령 |

```text
동일한 Hybrid 후보 100개
  → 상위 10청크에서 허용 관계의 evidence를 역조회
  → Service/Article 시작점 최대 5개
  → 허용 관계를 정방향으로 최대 2-hop 탐색
  → Graph 후보 100개와 Hybrid 후보 100개를 RRF로 결합
  → 최종 10개 평가
```

관계 목록은 **시작점 바인딩 역조회와 실제 탐색 모두**에 적용된다. 실제로 204문항 중 26문항에서 시작 노드 목록이 바뀌었다. 그러므로 이 결과를 “시작점은 고정하고 탐색 엣지만 추가한 효과”라고 해석하면 안 된다. 시작 노드 유형은 계속 Service/Article이며, 도착 노드로는 Document·Agency·Law까지 탐색한다.

## 2. 비교 조건과 검증

- 입력: `20261027_052016`의 저장된 Kiwi Hybrid 후보. 회사 모델/API 추가 호출 0회.
- 204문항 중 답변 가능 177문항을 검색 지표로 평가하고, 27문항은 진단용으로 분리했다.
- 동일한 그래프·evidence·쿼리·Hybrid 후보·Kiwi 점수·RRF 상수 60·탐색 예산을 사용했다.
- 두 조건을 동일한 현재 코드로 재실행했고, **2개 조건의 질문별 예측 전체가 기존 결과와 정확히 일치**함을 확인했다.
- 예산 초과로 탐색이 잘린 문항은 두 조건 모두 0개였다.
- 이번 실험은 기본 Extension의 관계 정책 비교다. H1·H2·H3를 다섯 관계 조건으로 다시 평가한 결과는 아니다.

## 3. 전체 벤치마크

| 방식 | 전체 근거 회수 | 일부 회수 | 미발견 | Recall@10 | 전체 근거 회수율 | MRR@10 |
|---|---:|---:|---:|---:|---:|---:|
| Hybrid 단독 | 140/177 | 11 | 26 | 82.20% | 79.10% | 0.6061 |
| Extension · 2개 관계 | 132/177 | 12 | 33 | 77.97% | 74.58% | 0.5579 |
| Extension · 5개 관계 | 142/177 | 9 | 26 | 82.77% | 80.23% | 0.6118 |

**2개 대비:** Recall +4.80%p, 전체 근거 회수 +10문항. 근거 회수량이 늘어난 문항 10개, 줄어든 문항 1개, 동일한 문항 166개다. 악화된 1개는 부분 회수→미발견이어서 전체 회수 문항의 증가분을 줄이지 않는다.

**Hybrid 대비:** Recall +0.56%p, 전체 근거 회수 +2문항. 근거 회수량 증가 9개·감소 6개·같은 개수지만 다른 근거를 찾은 경우 1개다. 전체 성능이 올라도 Hybrid의 개별 성공 사례를 모두 보존한 것은 아니다.

Recall은 각 질문의 필수 근거 그룹 회수 비율을 평균한 값이다. “전체 근거 회수”는 그 질문의 모든 필수 그룹이 Top-10에 있는 경우다. 답변 생성 정확도는 평가하지 않았다. 같은 평가셋에서 관찰한 개선이며 통계적 유의성이나 새 질문에 대한 일반화는 검증하지 않았다.

## 4. 어떤 질문에서 달라졌나

| 질문 유형 | 문항 | Hybrid 전체 회수 | 2개 전체 회수 | 5개 전체 회수 | 2개 Recall | 5개 Recall |

| 직접 질의 | 45 | 43 | 41 | 42 | 91.11% | 93.33% |

**제출서류는 10/19→17/19로 회복**해 Hybrid와 같은 전체 회수 수에 도달했다. 다중 출처·다중 hop은 5문항 중 한 문항의 부분 근거를 잃어 Recall이 60%→50%로 내려갔다. 처리기관 유형은 1문항뿐이므로 그 유형의 집계만으로 HANDLED_BY의 효과를 일반화할 수 없다.

## 5. 개선·악화의 실제 경로

### 제출서류 경로 복구: SJ-A-029

한부모가족증명서 신청에서 주민등록증과 운전면허증을 둘 다 가져가야 하는지 묻는 질문이다. 두 조건의 시작점은 같았다. 5개 조건에서 `Service → REQUIRES → Document`를 따라 정답 청크가 Graph 후보에 들어왔다. Hybrid 2위였던 청크는 2개 조건에서 Graph 순위가 없어 결합 14위였지만, 5개 조건에서는 Graph 3위·결합 2위로 회복됐다. 기존 evidence를 실제로 활용한 개선이다.

### 처리기관 연결을 통해 절차 청크 회수: SJ-N-025, SJ-A-059

N025는 여권용 납세증명의 처리기간, A059는 농지대장 발급·수정의 처리기간을 묻는다. 정답은 둘 다 신청 방법·절차 청크에 있다. HANDLED_BY의 원문 연결을 통해 그 청크가 Graph 후보에 들어오며 각각 결합 13→2위, 16→3위로 회복됐다. 기관 엣지가 처리기간을 직접 표현하는 것은 아니다. **기관 정보와 처리기간이 같은 청크에 있어 회수에 도움이 된 것**이다.

### 시작점 자체의 개선: SJ-N-027

“회사랑 장사해서 번 돈을 증명하는 서류”를 묻는 질문이다. 2개 조건은 법 조항 5개에서 시작했고, 5개 조건은 새 관계의 바인딩을 통해 소득금액증명 Service를 시작점에 포함했다. 그 서비스의 0-hop 안내 evidence로 정답을 회수했다. Hybrid 60위·기존 결합 64위였던 청크가 새 결합 8위가 됐다. 이는 추가 엣지를 따라간 효과만이 아니라 진입점 선택이 달라진 효과다.

### 유일한 악화: SJ-N-057

국세·지방세 납세증명의 각각의 근거 법을 묻는 질문이다. 두 조건의 시작점은 같고, 지방세징수법 제5조 청크의 Graph 순위도 3위로 같았다. 그러나 HANDLED_BY로 연결된 신청 절차 청크 두 개가 새 최종 4위·6위로 들어왔다. 법적 근거 청크는 결합 10→12위로 밀려 부분 회수→미발견이 됐다. 필요한 조항으로 가는 경로가 없어졌거나 탐색 예산을 초과한 문제가 아니라 **추가 후보와의 최종 순위 경쟁 문제**다.

국세징수법 제108조는 두 조건 모두 Graph 경로가 없고 Hybrid 43위여서 Top-10에 들어오지 못했다. 따라서 이 질문은 관계를 더 허용하는 것만으로 두 근거를 모두 회수하지 못한다.

### 경로를 찾았다는 것과 조건을 이해했다는 것은 다르다

A032의 법정대리인 질문에서는 회수 경로의 짧은 인용이 “위임장 제출”이고, B037의 여권정보 질문에서는 “제적등본”이다. 정답을 담은 같은 청크를 찾아 검색 평가에서는 성공하지만, 해당 인용만으로 법정대리인 예외나 여권정보 조건을 입증한 것은 아니다. 이후 답변을 만들 때는 회수된 청크의 조건·대안 문장 전체를 확인해야 한다.

## 6. 결과를 어떻게 해석하고 다음에 무엇을 할까

**관계를 모두 허용한 설정은 현재 기준으로 유지할 만하다.** 두 관계만 사용하면서 생긴 제출서류·절차 근거 손실을 상당 부분 회복했다. 현재 `hybrid_graph.py`와 `run_week4.py`의 기본값은 다섯 관계다.

다만 최종 후보 풀의 정답 그룹은 204문항 모두 두 조건에서 동일했다. 후보 풀 Recall은 둘 다 98.02%이고, Graph 후보 Recall은 72.88%→83.33%다. 이번 증가는 주로 **이미 Hybrid 후보에 있던 정답에 Graph 점수가 붙어 최종 순위가 회복된 결과**다. 추가 원문이나 새로운 정답을 대량 발견한 결과라고 설명하면 안 된다.

다음 개선은 관계를 무조건 더 늘리는 것보다 다음 지점을 겨냥하는 것이 타당하다.

1. **질문과 관계의 적합성을 순위에 반영:** N057처럼 법적 근거 질문에서 기관·절차 청크가 근거 조항을 밀어내는 현상을 줄인다. 정답 질문 유형을 입력하지 않고 실제 질문 텍스트로 판단해야 한다.
2. **관계별 효과를 분리:** 이번에는 세 관계를 동시에 추가했고 시작점도 변했다. REQUIRES만 추가, HANDLED_BY만 추가, PART_OF만 추가 및 시작점 고정 실험으로 각 기여를 분리해야 한다. 특히 PART_OF가 독립적으로 도움이 됐다고 단정할 근거는 아직 없다.
3. **다섯 관계 기준에서 H1·H2·H3 재평가:** 이 비교 당시의 후속 과제였으며, 현재는 `20261027_091116`에서 완료했다. 최신 [통합 보고서](REPORT.md)에 독립 비교 결과를 정리했다. 가설별 증가분을 누적 개선으로 합산하지 않는다.

Hybrid 대비 여전히 회수량이 감소한 질문은 SJ-N-048·051·056, SJ-A-001·056, SJ-B-022다. SJ-N-039는 회수 개수는 같지만 얻은 근거와 잃은 근거가 다르다. 이 사례들은 새 설정에서도 후속 실패 분석 대상으로 남는다.
