## 2. 누적 근거와 첫 검색 재정렬

**질문** · 검색할 때마다 쌓이는 근거는 어떻게 보관되고, 후보 100개에는 있지만 최종 10개에서 빠지는 문제는 재정렬로 줄일 수 있는가.

**현재 정책** · 각 검색은 BGE 순위 상위 10개를 반환한다. 본문은 ID별로 누적되고, 추가 탐색 중에는 최신 결과, 종료 예산에 가까워지면 확인 항목에 연결한 근거를 우선해 최대 60,000자 범위에서 전달한다. 답변형 488문항에서 B/C가 확보한 지정 근거의 최종 전달 손실은 0건이었다.

**재정렬 대안** · 첫 검색 실패 53문항 중 47문항은 후보 안 순위 문제, 6문항은 후보 자체 누락이었다. 보존된 후보와 BGE 순위는 그대로 두고, 질문과 본문의 IDF 가중 어휘 일치 순위를 RRF(`k=60`)로 더하는 대안을 CPU에서 비교했다. 순위 결정에 정답은 쓰지 않았고, 488문항의 코퍼스 지문과 BGE 상위 10개가 보존 원본과 일치함을 확인했다.

| 첫 검색 분류 | 문항 | 대안 결과 |
|---|---:|---|
| BGE 상위 10개에서 완전회수 | 435 | 404 유지, 31 퇴보 |
| 후보에는 있으나 상위 10개에서 누락 | 47 | 13 회복, 34 미회복 |
| 후보 자체에서 누락 | 6 | 6 미회복 |

**판단** · 완전회수는 BGE **435/488(89.14%)**, 대안 **417/488(85.45%)**로 18건 줄었다. 전체 재정렬은 기존 BGE를 유지하고, 누적 본문 보존 정책을 바꿀 근거도 나오지 않았다. 대안의 추가 CPU 시간은 평균 약 1.5ms이나 BGE 계산 시간과는 직접 비교할 수 없다.

## 3. Planning 필요성과 효과

**질문** · 처음에 확인 항목을 만드는 과정이 필요한 질문이 얼마나 있고, 기존 문항과 추가 복합 문항에서 효과는 어떻게 다른가.

**문항 구성** · 기존 608문항의 저장된 추론 분류는 직접형 140, 한 단계·복수 근거·다단계·인용 연결 37, 미판정·미해결·분류 없음 431개다. 이 분류는 Planning이 도움이 된 문항 수와 다르다. 추가 복합 392문항은 두 사람의 문의를 분리해야 하며 답변/답변 312, 답변/확인 질문 40, 답변/보류 40개다.

**실험 흐름**
1. 첫 비교(12문항): 계획을 비우라고 한 조건도 12/12건에서 확인 항목을 반환했다. 조작이 되지 않아 효과를 판단하지 않았다.
2. 보정 비교(12문항): 같은 근거로 바로 답변하는 조건과, 별도 계획 호출 후 같은 지침으로 답변하는 조건을 비교했다. 효과는 없었다(기존 6문항 2/6 → 2/6, 복합 6문항 5/6 → 5/6).
3. 38문항 확대: 기존 20문항 + 복합 18문항(답변/확인 질문/보류 각 6개), 114개 호출 모두 정상 반환. 변형 이름을 가린 Qwen 루브릭 채점(기대 행동·필수 내용·금지 주장)으로 판정했고, 차이가 난 6문항은 사유를 직접 읽었다.

| 문항군 | 바로 답변 | 계획 전달 | 응답 시간(계획 호출 포함) | 총 토큰(계획 호출 포함) |
|---|---:|---:|---|---|
| 기존 20문항 | 14 | 17 | 4.5초 → 6.9초 | 5.3k → 10.4k |
| 복합 18문항 | 14 | 15 | 7.5초 → 8.5초 | 9.1k → 17.7k |

- 개선 5건 중 3건은 확인 질문이 필요한 문항이다(`W7V2-BH002`, `W8-COMP-0332`, `W8-COMP-0348`). 바로 답변은 단정하거나 답변으로 끝냈고, 계획 조건은 필요한 사실을 물었다. 나머지 2건(`W7-MS-013`, `SJ-N-028`)은 조건·예외 구분과 조항 연결이 더 담겼다.
- 퇴보 1건(`W8-COMP-0175`)은 법적 근거 조항을 표기하지 않았다. 복합 문항의 A/B 구분 구조는 18개 중 15개에서 두 조건이 같았다.

## 4. Graph 사용과 역참조

**질문** · Graph를 쓸 수 있는데 성능 개선으로 이어지지 않은 이유는 무엇이고, 보류한 개선 항목과 역참조는 어떻게 되는가.

**사용 현황** · C에서는 608문항 모두에 Graph 후보가 표시됐으나 실제 호출은 13문항 15회(직접 조회 9, 관계 탐색 6)였다. 새 필수 근거가 추가된 호출은 3회다. B→C에서 최종 필수 근거 회수는 5문항 개선·3문항 퇴보였는데, 개선 중 실제로 Graph를 선택한 것은 `SJ-N-050` 한 건이다.

**원인 분석 (C에서 최종 필수 근거가 빠진 28문항)**

① **도달 가능성**(CPU): 표시된 후보를 직접 조회하거나 관계 한 홉을 탐색했을 때 빠진 근거가 반환되는지 저장 Graph로 재현했다.

| 측정 | 문항(28) |
|---|---:|
| C가 실제로 Graph를 호출 | 2 |
| 후보 중 하나라도 빠진 근거에 도달 | 25 |
| 후보 직접 조회로 도달 | 19 |
| 현재 나가는 방향 관계 한 홉으로 도달 | 5 |
| 들어오는 방향(역참조)에서만 도달 | 6 |
| 어떤 후보로도 도달 못함 | 3 |

② **Qwen의 선택**(84회): 같은 28문항의 C 첫 입력을 재사용해 허용 행동과 후보 수만 바꾸고, 선택한 요청을 저장 Graph에서 실행해 채점했다. 정답은 모델에 보이지 않았다.

| 조건 | 선택한 행동 | 빠진 근거 확보 | 형식 오류 |
|---|---|---:|---:|
| 원래 허용 행동(검색·Graph·응답) | 응답 21, 검색 6, Graph 0 | - | 1 |
| Graph만 허용 | Graph 28 | 6/28 | 0 |
| Graph만, 후보 앞 8개만 | Graph 28 | 5/28 | 0 |

- **병목은 후보 선택 이전의 판단이다.** Graph가 가능한 상태에서도 0/28이고, 21문항은 근거가 빠졌는데 응답을 택했다. 억지로 Graph를 쓰게 해도 6/28이며, 도달 불가능한 대조 3문항은 전부 0건이었다.
- **"후보가 많아서 못 고른다"는 가설은 뒷받침되지 않았다.** 후보를 8개로 줄여도 6→5였다(후보는 문항당 중앙값 23개, 도달하는 후보는 중앙값 3개). 후보 8개 조건에서 5문항은 문서 후보 ID를 직접 읽었고 그중 4문항이 빠진 근거를 얻었다. 5문항 규모라 가능성 수준이다.
- **역참조**: 도달 경로를 추가하는 문항은 6개이고, Qwen이 고른 요청을 양방향으로 실행해도 새로 확보한 문항은 1건이었다. `SJ-B-034`에서 같은 시작점의 방향을 바꾸면 나가는 방향은 필수 근거 두 묶음 중 후자만, 들어오는 방향은 주거급여법 시행규칙 제2조 본문을 포함한 전자만, 양방향은 둘 다 반환했다. 도구 호출에 시작점을 지정한 결과이므로 회의의 후속 계획 범위로 두고, Qwen의 자율 선택 효과는 별도 평가가 필요하다.

**보류했던 보완 가능성** · `W7-MS-033`은 모든 지정 청크를 강제하지 않고 답변에 필요한 대체 근거를 읽어야 하는 사례다. `W7V2-MS038`은 서로 다른 규정 중 적용 범위를 판단할 연결 근거가 필요한 사례이며, C의 추가 검색은 누락 근거를 확보하지 못했다.

**입력 크기** · `W7V2-MS008`은 법령 문서 조회 후 다음 입력이 664,549자로 늘어 모델 호출이 실패했다. 본문 60,000자 제한과 별개로 조문 목록에도 입력 한도를 적용하는 구현 후보가 확인됐다.

**한계** · 첫 입력 한 시점의 재생이며 모델당 한 번 생성했다. 도달 가능성은 상한값이다(25문항의 첫 검색 후보에는 필요한 청크가 있어 순위 문제와 겹친다).

## 5. 재질문 이후 상태 유지·재개

**질문** · 사용자에게 추가 정보를 물은 뒤 기존 근거와 진행 상태로 이어갈 수 있는가, LangGraph/LangChain으로 전환할 가치가 있는가.

현재 컨트롤러는 `respond`에서 끝난다.

**실험 1 · 상태 저장·복원(`W7V2-BH002`)** · 보존된 B의 근거 10개, 확인 항목, 검색 이력을 SQLite에 기록하고 새 연결에서 복원했다. 채널 미확인 입력에는 질문을 반환했고, 인터넷/무인발급기 응답으로 각각 이어갔을 때 저장된 근거 ID를 재사용했으며 새 검색은 0회였다. 이미 채널이 있는 입력은 즉시 결과를 반환했고, 같은 답의 재요청·두 세션의 분리·이전 완료 결과와 충돌하는 답의 거절을 확인했다. 단, 응답 문장은 코드에 고정된 한 사례의 규칙이다.

**실험 2 · Qwen이 이어 답하기(6문항, 확인 질문 점검 3회 실행)** · 저장된 근거 ID와 확인 질문, 가상의 사용자 답장을 Qwen에 다시 넣어 새 도구 호출 없이 이어 답하게 했다. 모든 응답이 정상 반환됐고, 근거 ID 표시는 1차 2/6, 2차 5/6, 3차 4/5였다. 근거 밖 주장은 직접 검수가 필요하다.

**실험 3 · 정답이 있는 5문항(Qwen이 사용자 역할)** · 벤치마크에서 재질문 뒤 정답 요지(`resolved_gold_answer`)가 있는 확인 질문형 5문항에 대해, 점검 단계의 질문 → Qwen 사용자 답장(숨은 실제 상황 기준, 모르면 모른다고 답함) → 저장된 첫 검색 근거만으로 응답을 이었다.

| 문항 | 저장 근거가 재질문 후 필요한 근거를 포함 | 사용자 답장 | 정답 요지 일치(Qwen 판정) | 근거 없는 단정 |
|---|---|---|---|---|
| `SJ-N-065` | 예 | 회사 요구, 가족 전원 | 일치 | 없음 |
| `SJ-N-066` | 아니오 | 모르겠다 | 불일치 | 있음 |
| `SJ-N-067` | 아니오 | 등기부 | 일치 | 없음 |
| `SJ-N-069` | 아니오 | 모르겠다, 세목별 과세 내역 필요 | 일치 | 없음 |
| `SJ-N-084` | 아니오 | 인터넷 등기 열람, 일부만 앎 | 불일치 | 있음 |

- 5문항 모두 점검 단계가 질문했고 응답은 모두 정상 반환됐다. 정답 요지 일치는 3/5이다.
- **재질문 뒤 필요한 근거를 첫 검색 근거가 이미 담은 경우는 1/5**였다. 일치한 3문항 중 2문항은 그 근거를 담지 않았는데도 일치로 판정됐다(질문이 쉽거나 판정이 관대했을 수 있다).
- 사용자가 "모르겠다"고 답한 `SJ-N-066`, `SJ-N-084`에서는 일반 설명으로 빠지거나 근거 없는 단정이 나왔다. 정보를 얻지 못한 재질문 뒤에는 다시 묻거나 보류하는 처리가 필요하다.
- 한계: 5문항이며 판정은 Qwen 초안이다. 재질문 뒤 새 검색을 하는 조건은 시험하지 않았다.

| 방식 | 재개 동작 | 전환 시 필요한 작업 |
|---|---|---|
| 현재 컨트롤러 확장 | 물어볼 필드와 근거 상태를 저장하고, 후속 입력에서 세션 ID로 복원 | 상태 직렬화, 세션 저장소, 원자적 갱신, 검색·모델 호출 한도, API의 대기/완료 응답 정의 |
| LangGraph | checkpointer로 상태를 보관하고 `thread_id`, `Command(resume=...)`로 재개 | 현재 루프를 노드로 옮기고 검증·도구 캐시·호출 한도·이력 형식을 재연결. 재개 시 중단 노드가 처음부터 실행되므로 외부 호출 위치를 정해야 함 |
| LangChain | 에이전트의 단기 메모리를 checkpointer와 스레드에 연결 | 메시지와 상태는 보관 가능. 근거 제한, Graph 커서, 재개 분기, A/B/C 실험 규칙은 별도 이식 |

**판단** · 기존 컨트롤러를 바탕으로 필요한 상태와 재개 계약을 우선 검증한다. 상태 저장만으로는 재질문 뒤 필요한 근거가 부족한 경우가 많아(1/5), 재질문 답을 반영한 재검색 단계를 재개 계약에 넣어야 한다. 지금 확인한 범위에서는 전면 마이그레이션을 정당화하기 어렵다. 다중 중단이나 장애 복구까지 요구가 확대되면 LangGraph를 다시 비교한다.

## 6. 성공·실패군의 개선과 비용

**질문** · 이미 근거를 잘 찾던 문항은 답변도 잘하는가, 잘 찾지 못하던 문항을 따로 묶어 비용을 줄일 수 있는가.

**군 구분** · 답변형 488문항을 기존 성공 435, 후보 안 순위 탈락 47, 후보 누락 6으로 나눴다. 같은 원본의 내용 채점 표본 48문항에서 첫 검색 완전회수 43문항의 자동 통과는 A 40·B 36·C 40건, 미회수 5문항은 A 3·B 5·C 5건이다. 5문항은 표본이 작고 완전회수와 답변 품질은 별개다.

**비용**(원본 병렬 실행 환경의 문항별 평균)

| 실험군 | 기존 성공: 응답 시간 / 모델 호출 | 순위 탈락: 응답 시간 / 모델 호출 |
|---|---:|---:|
| A | 33.73초 / 1.00회 | 38.59초 / 1.00회 |
| B | 38.20초 / 1.11회 | 55.17초 / 1.66회 |
| C | 39.63초 / 1.18회 | 57.05초 / 1.74회 |

실패군에 반복 검색을 적용하면 시간이 늘었다.

**재정렬 결과 답변 비교(8문항)** · 회복·퇴보·유지·계속 실패에서 2문항씩 골라 두 순위의 상위 10개로 Qwen 응답을 생성했다. 16개 모두 형식 검사를 통과했고, 핵심 내용은 직접 검수했다.

## 실행 환경과 재현

팀 GPU 작업이 필요한 항목은 없었다. 488문항의 대안 재정렬은 원본 BGE 순위를 재사용해 CPU로 실행했다. Qwen 생성 API 호출은 Planning 36회, 재정렬 답변 16회, Planning 확대 비교 114회와 채점 76회, 확인 질문 점검과 재개 약 41회, Graph 선택 재생 84회, 확인 질문 60문항 확대와 5문항 재개 약 190회다. 새 후보 생성·BGE 재채점까지 포함한 608문항 실험을 하게 되면 그때 GPU 환경을 사용한다.
