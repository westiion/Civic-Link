# QA Taxonomy

| 코드 | 유형 | 정의 | 문항 수 |
| --- | --- | --- | --- |
| service_discovery | 필요 민원 찾기 | 사용 목적을 서비스의 공식 명칭과 ID에 연결한다. | 5 |
| direct_qa | 단순 사실 | 한 안내 항목에서 직접 확인되는 사실·포함 여부를 답한다. | 5 |
| requirement_condition | 발급 요건·조건 | 신청자·본인확인·신청 채널 등 발급 요건을 확인한다. | 4 |
| legal_grounding | 법적 근거 | 서비스·요건의 근거 법령과 조·항을 특정한다. | 4 |
| cross_reference | 참조 조문 | 근거 조문이 명시적으로 인용하는 조문을 1-hop으로 연결한다. | 4 |
| multi_source_multi_hop | 복수 근거 종합 | 서로 다른 출처·조문에 있는 독립적인 답변 요소를 종합한다. | 4 |
| unanswerable | 답변 불가 | 범위 밖이거나 증거·신청 맥락이 부족하여 결론을 확정할 수 없다. | 4 |

## 분류 기준

1. 범위와 근거의 충분성을 먼저 판정. 범위 밖 또는 맥락 부족이면 `unanswerable`로 분류.
2. 서비스 이름을 찾는 것이 목적이면 `service_discovery`, 발급 조건을 묻는다면 `requirement_condition`으로 분류.
3. 법령/조항의 식별은 `legal_grounding`, 인용된 다른 조문의 내용은 `cross_reference`로 구분. 두 조문을 사용한다는 이유만으로 참조형을 복수 근거형으로 바꾸지 않음.
4. 서로 독립적인 답변 요소에 여러 출처가 필요한 경우에만 `multi_source_multi_hop`을 부여. 동일 문단에 답이 모두 있으면 다중 근거형으로 분류하지 않음.
5. 나머지 직접적인 사실 확인은 `direct_qa`로 분류함.

## 답변 불가

| 코드 | 의미 | 응답 기준 |
| --- | --- | --- |
| OUT_OF_SCOPE | 위치/시간/실시간 상태/개인 조회/외부 심사 등 범위 밖 | 범위를 설명하고 결론을 만들지 않음. |
| INSUFFICIENT_EVIDENCE | 범위 안이지만 증거 또는 신청 맥락 부족 | 빠진 정보와 확인 사항을 명시함. |
| SOURCE_CONFLICT | 적용 대상/채널/시점이 같은 공식 자료의 미해결 충돌 | 충돌을 설명하고 정답 확정을 유보함. |
