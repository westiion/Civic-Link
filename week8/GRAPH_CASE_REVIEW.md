# Week7 순위 탈락 44문항 — Graph 도구 설계 검토

질문별로 **실패한 단계 → Qwen이 볼 수 있는 단서 → 다음 행동 → 필요한 도구 기능**을 대조한 설계 검토 기록이다. 44문항별 다음 행동은 당시의 제안이며, 이후 구현 현황은 아래 기능 표와 [에이전트 설계](AGENT.md#구현-현황)에 구분한다. 시작점 개수·홉 수·후보 정렬 기준은 이 사례 분석만으로 확정하지 않는다.

## 분석 기준

- **대상:** Week7 최종 BGE 기준선에서 `complete10=0`, `complete100=1`인 44문항, 놓친 필수 근거 49묶음. 후보 전체가 누락된 7문항은 제외했다.
- **관찰 입력:** 질문 원문과 당시 BGE 상위 10개 본문을 Qwen에게 제공한다고 가정한다. Week8의 현재 Hybrid+BGE 첫 검색 결과를 실행한 분석은 아니다.
- **분석용 정답과 모델 입력을 분리:** 정답 근거·원래 순위·Graph 경로는 실패 위치를 진단하는 데만 사용한다. 다음 행동은 질문·상위 본문에 드러난 대상과 표현으로 제안하며, 아직 읽지 않은 정답 조문 번호·정답 문구를 Qwen에게 주지 않는다.
- **확인한 사실과 제안을 분리:** 저장된 순위·시작점·경로는 기록 대조 결과다. Qwen의 다음 행동과 추가 쿼리는 설계 가설이며, 모델 실행이나 검색 재실험으로 성공을 검증한 결과는 아니다.
- **답변 가능성:** 기존 사례집의 ‘모두 확인 10·일부 확인 11·확인 못함 23’은 유지한다. 이 문서의 ‘응답 범위 재검토 6문항’은 별도 검수 제안으로, 기존 정답표나 지표를 변경하지 않는다.
- **자료 범위:** 저장된 코퍼스의 내용으로 검색 구조를 분석했다. 현재 법령에 대한 안내나 독립적으로 검수된 실제 민원 정확도 평가가 아니다.

## 어디에서 실패했는가

| 놓친 49개 근거 묶음의 기존 Graph 상태 | 묶음 수 | 해석 |
|---|---:|---|
| Graph 상위 10개에 이미 있었음 | 20 | Graph가 찾았어도 최종 BGE 10개에서 탈락할 수 있음 |
| Graph 11~100위에 있었음 | 7 | 탐색에는 성공했지만 Graph 내부 순위와 최종 선택을 함께 봐야 함 |
| 기존 Graph 탐색에서 수집되지 않음 | 22 | 전체 합집합에서는 Hybrid가 확보. 시작점·방향·연결·근거 연결을 따로 진단해야 함 |

문항 기준으로는 **23문항에서 놓친 근거 전부를 기존 Graph가 이미 수집**했고, **21문항에서는 놓친 근거를 Graph가 수집하지 못했다.** 이 수치는 ‘Graph를 다시 쓰면 성공한다’는 뜻이 아니다.

44문항 모두 기존 탐색 기록에 노드·간선 예산 초과가 없었고, 질문별 Graph 후보는 최대 64개였다. 따라서 이 집합에서는 **Graph 후보 100개 제한에서 잘린 것**이 원인은 아니었다. 시작점 5개·진입 청크 10개·탐색 방향·2홉 제한의 영향은 별개다.

## Graph 도구 요구와 후속 구현

아래는 44문항 분석에서 도출한 요구를 후속 구현과 대조한 표다. 기능 구현 여부와 각 실패 문항의 실제 해결 여부는 별도로 확인한다.

| 기능 | 필요한 이유·대표 사례 | 후속 구현·남은 검토 |
|---|---|---|
| **대상 식별** | 질문 또는 읽은 자료에 등장한 서비스·조문을 실제 노드로 확인. `SJ-N-051`, `W7-MS-036`처럼 검색 상위에서 빠진 대상에도 접근할 필요 | 질문의 고유한 이름·별칭, 전달한 근거, 이전 Graph 결과에서 관찰한 후보를 누적·중복 제거해 Qwen에 제공 |
| **노드에 직접 연결된 근거 조회** | 이미 서비스는 찾았지만 신청자격·발급서류·안내 내용이 빠짐. `SJ-A-008`, `W7-PR-012` | `mode=direct`로 노드에 연결된 근거나 문서 본문을 직접 조회. 본문 한도를 넘으면 커서로 이어 읽기 지원 |
| **명시적 인용의 원문 조회** | 읽은 조문이 필요한 원문을 지목함. `SJ-N-050`, `W7V2-MS041` | `mode=traverse`와 `relation=REFERENCES`로 인용 관계와 연결 본문 조회. 시작점은 `target_type`·`target_id`, 선택할 연결 대상은 `destination_id`로 지정 |
| **인용하는 조문 조회** | 읽은 규정의 적용 연결이 반대 방향에만 있음. `SJ-B-034` | 에이전트의 Graph 탐색은 나가는 방향 1홉을 사용. 역방향 인용 조회는 추가 검토 대상으로 유지 |
| **관계와 본문의 연결·조건 보존** | 서류명만으로 위임장 예외를 판단하거나 같은 용어의 다른 제도 정의를 섞지 않아야 함. `W7-MS-039`, `W7-MS-044` | 연결 본문·출처·반환 범위와 이어 읽을 위치를 제공하고, Qwen이 대상·행위자·시점과 적용 조건을 검토하도록 입력 지침에 반영 |

**근거 보존과 검색 전환은 중앙 프로그램·Qwen의 책임도 포함한다.** 확인 항목에 연결한 근거가 다음 입력에서 빠지지 않도록 관리하고, 현재 노드의 주변에 답이 없으면 목표를 바꿔 `search`할 수 있어야 한다. 같은 입력의 Graph 호출을 반복하는 것만으로는 새로운 근거가 생기지 않는다.

서비스 이름이나 인용 조문이 이미 보이는 경우에는 그 단서에서 출발할 수 있다. 따라서 모든 질문에 **‘전체 후보에서 20개 선정’**을 공통 선행 단계로 둘 근거는 아직 부족하다. 후보 묶음 탐색은 대상이 모호하거나 선택지가 많은 사례에서 별도로 검증한다.

### 판단·도구·평가를 분리할 점

| 구분 | 확인할 내용 |
|---|---|
| Qwen 판단 | 실제 관찰만으로 미확인 항목을 찾고, 적절한 대상·관계·검색어를 선택하는가 |
| 도구 실행 | 선택한 노드·관계에 연결된 필요한 본문을 반환하는가. 근거 ID·출처·경로·반환 범위가 보존되는가 |
| 결과 누적 | 두 비교 대상 또는 여러 확인 항목의 근거를 함께 유지하는가 |
| 종료 | 현재 본문으로 이미 답할 수 있는데도 정답표의 특정 청크를 찾으려고 계속 검색하지 않는가 |
| 평가 | 지정 근거 회수와 실제 답변의 주장·인용 충족을 나누어 본다. 이 분석에 사용한 문항을 독립 검증셋으로 부르지 않는다 |

## 44문항별 검토

아래 분류는 **이번 분석에서 제안한 첫 대응**을 기준으로 한 상호 배타적 구분이다. 기존 실패 유형 1~5는 중복 분류이므로 그 건수와 합산하지 않는다.

| 첫 대응 제안 | 문항 수 | 의미 |
|---|---:|---|
| 현재 근거를 검토해 응답 | 10 | 기존 사례집에서 대체 근거로 필요한 내용을 모두 확인한 문항 |
| 보이는 서비스의 직접 근거 조회 | 6 | 서비스 단서는 있으나 필요한 안내 항목이 비어 있음 |
| 관찰한 조문의 인용 원문 조회 | 7 | 상위 본문에 필요한 인용 단서가 있음 |
| 대상·업무·시점을 좁힌 조회 또는 재검색 | 14 | 다른 대상을 확보하거나 검색 목표를 교정해야 함 |
| 역방향 인용 조회 검토 | 1 | 현재 조문을 인용하는 적용 조항을 확인할 필요 |
| 응답 범위·추가 탐색 필요성 재검토 | 6 | 핵심 요청은 이미 답할 가능성이 있어 보충 근거를 강제할지 검수 필요 |
| **합계** | **44** | Qwen 실행 성공률을 뜻하지 않음 |

각 문항을 펼치면 **실패 위치·관찰 단서·다음 행동·원래 경로**를 볼 수 있다. H/G/B는 각각 Hybrid·Graph·최종 BGE 순위이며, `—`는 해당 분기에서 근거를 확보하지 못했다는 뜻이다.

**순위 해석:** H/G/B는 각 필수 근거 묶음에서 허용된 청크 중 해당 방식의 가장 높은 순위다. 같은 행의 H/G/B가 반드시 같은 청크를 가리키는 것은 아니다. 경로는 허용 청크를 수집한 경로의 예다.

**연결 대조의 의미:** 상위 10개 근거와 Graph 노드의 연결·인용 방향은 저장 데이터로 확인했다. 그 목록이 현재 Qwen 입력에 자동 제공된다는 뜻은 아니다. 도착 조문의 내용도 실제 조회 전에는 확보한 근거로 간주하지 않는다.

## 다음 검증에서 결정할 것

1. **서비스 직접 근거 조회부터 기능 단위를 정한다.** 기존 경로가 0홉인데 현재 관계 조회만으로 빠진 항목을 읽을 수 있는지 확인한다. 후보 개수를 늘리기 전에 반환해야 할 근거의 범위를 정한다.
2. **관찰한 인용에서 재진입하는 방식을 확인한다.** 현재 본문의 인용을 Qwen이 인식하고, 그 조문을 실제 노드로 식별해 원문을 조회하는지 본다. 정답 노드를 미리 제공하는 실험과 구분한다.
3. **비교 대상·업무·시점의 누락을 탐지하는지 확인한다.** 도구가 맞는 본문을 반환하는 문제와 Qwen이 적절한 목표를 선택하는 문제를 따로 평가한다.
4. **이미 충분한 근거가 있을 때 멈추는지 확인한다.** 기존 대체 근거 10문항과 응답 범위 재검토 6문항을 사용해 불필요한 추가 탐색을 점검한다.
5. **그다음 후보 수·홉 수·반복 예산을 정한다.** 실제 필요한 행동이 확인된 뒤 후보 표시·재조회 정책을 비교한다. 이번 기록만으로 20개 제한이나 출처별 균등 선정을 채택하지 않는다.
