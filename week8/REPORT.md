# Week 8 — 벤치마크 1,000문항 확장

이번 작업은 **벤치마크 확장**이다. 기존 Week 7의 608문항을 그대로 두고, 기존 근거에서 구성한 복합 과제 392문항을 별도 버전에 추가했다. Agent 구현·새 모델 실험은 작업 범위에 포함하지 않는다.

버전: `week8-composition1000-v1`

## 구성

| 기대 행동 | 보존 문항 | 추가 문항 | 합계 |
|---|---:|---:|---:|
| 답변 가능 | 488 | 312 | 800 |
| 추가 확인 | 60 | 40 | 100 |
| 답변 보류 | 60 | 40 | 100 |
| 전체 | 608 | 392 | **1,000** |

추가 문항은 두 사람의 독립적인 문의 A/B를 한 요청에 담은 합성 과제다. 같은 서비스에 관한 문의를 연결하지만, 한쪽의 조건·신원·기록을 다른 쪽에 적용하지 않도록 명시한다.

- **복합 답변 312개:** 서로 다른 질문 유형을 결합한다. 각 문의가 별도 검색 근거를 추가하고, 합쳐 최소 2개 원문 문서를 요구한다. 문서 수를 실제 그래프 홉 수로 해석하지 않는다.
- **부분 안내 + 추가 확인 40개:** 한 문의는 답변 가능하고 다른 문의는 정보가 부족하다. 부족한 슬롯을 확인하면서 답변 가능한 부분을 놓치지 않는 문항이다.
- **부분 안내 + 보류 40개:** 한 문의는 답변 가능하고 다른 문의는 현재 자료·시스템 범위 밖이다. 공개 안내와 실제 발급·조회·기록 변경 등의 요청을 구분한다.

예를 들어 `W8-COMP-0313`은 A가 제적등본/초본 중 어느 것을 요구받았는지 모르는 상황과, B가 전체 가족 기록을 필요로 하는 상황을 함께 묻는다. B의 목적을 A에게 대신 적용하면 안 된다. `W8-COMP-0392`는 농지대장과 소유권이전등기의 관계 안내와 실제 대장 기록 변경 요청을 구분한다.

40개 서비스에 걸쳐 부모 문항 487개를 사용했고, 부모 1개당 최대 4회 재사용했다. 선정은 모델 점수 없이 서비스별 분포·부모 사용 빈도·질문 유형 조합을 고려한 고정 규칙으로 실행한다. 전체 질문 유형을 균등화한 데이터는 아니다.

## 데이터와 사용법

| 파일 | 용도 |
|---|---|
| [questions.jsonl](../data/benchmark/week8/questions.jsonl) | 전체 1,000문항과 정답·근거 |
| [new_questions.jsonl](../data/benchmark/week8/new_questions.jsonl) | 추가한 복합 문항 392개 |
| [queries.jsonl](../data/benchmark/week8/queries.jsonl) | 전체 입력용: `query_id`, `question`만 포함 |

| [questions.csv](../data/benchmark/week8/questions.csv) | 질문·기대 행동·정답·부모 ID를 확인할 검토용 목록 |
| [selection.jsonl](../data/benchmark/week8/selection.jsonl) | 선정된 부모 쌍과 서비스 기록 |

원본 608문항은 새 파일의 앞부분에도 바이트 단위로 그대로 보존한다. 따라서 기존 행의 `dataset_id=week7-master608`와 ID·정답·주석은 바꾸지 않았다. 전체 파일의 버전은 `dataset.json`과 manifest로 식별한다.

새 문항의 `agentic.subtasks`는 **정답 주석**이다. A/B별 부모 ID, 기대 행동, 정답, 필요한 근거, 확인 슬롯을 저장하며 실행 코드는 아니다. 모델 입력에는 이 주석을 제공하지 않고 `queries.jsonl`만 사용한다.

혼합 과제의 최상위 `expected_action`은 **해결되지 않은 문의에 필요한 행동**이다. `clarify`/`abstain`이라고 해서 다른 문의의 답변까지 생략해도 된다는 뜻은 아니다. 향후 응답 평가 시 A/B별 정답과 금지 사항을 모두 확인해야 하며, 기존 단일 행동 분류만으로 과제 성공률을 주장할 수 없다. 기존 검색 평가기는 전체 답변 가능한 800문항만 집계하므로 혼합 과제 안의 답변 가능한 부분은 별도 평가 설계가 필요하다.

```sh
# 저장소 루트, 기존 DB 복원 후
.venv/bin/python scripts/build_week8_benchmark.py verify

# 기존 디렉터리를 덮어쓰지 않는 재생성
.venv/bin/python scripts/build_week8_benchmark.py build --output-dir outputs/week8-rebuilt

# 데이터 보존·재현성·잘못된 인용 및 체크섬 거부 테스트
.venv/bin/python -m pytest tests/test_week8_benchmark.py -q
```

## 검증 결과

- 전체 테스트 `153 passed` (기존 150개 + 신규 데이터 테스트 3개). 신규 테스트에는 서로 다른 경로에서의 재생성과 모든 파일의 바이트 비교, 원문 인용·체크섬 변조 거부, 누수 그룹의 전이적 연결 검사가 포함된다.
- 1,000개 고유 ID, 정규화한 질문 문자열의 완전 중복 0개.
- 기존 608문항 원본 보존, 두 개의 별도 출력 경로에서 생성된 모든 파일이 바이트 단위로 동일.
- 전체 근거 인용 1,996건의 원문 구간·출처 URL·문서·청크 연결 검증.
- 신규 근거의 인용 범위가 허용 청크를 벗어나는 경우 0건. 기존 38문항의 넓은 인용은 과거 검색 정답을 바꾸지 않고 검증 기록에 남김.
- 40개 서비스에 추가 문항 존재, 부모 쌍 중복 방지, A/B 정답·슬롯을 부모로 추적 가능.
- 추론 입력은 질문 ID와 질문만 포함. 정답·행동·부모 ID는 별도 검토 데이터에만 포함.
- 누수 연결 그룹 58개, 가장 큰 그룹 854문항. 같은 청크·부모 관계·기존 의도/규칙 그룹의 전이적 연결을 기록함.

## 해석의 한계

**1,000개 독립 의도나 새로운 법률 지식을 수집했다는 뜻은 아니다.** 신규 392개는 기존 문의를 재조합한 개발용 문항이다. 전체 근거 청크 조합은 702종이며, 인용 검증은 의미적 정답성을 독립적으로 인증하지 않는다. 복합 요청의 자연스러움과 정답의 완전성은 문항별 사람 검수가 필요하다.

전부 `human_verified=false`, `independent_gold=false`, `independent_holdout=false`, `eligible_for_official_metrics=false`를 유지한다. 입력 표현을 바꾸었더라도 기존 문항과 같은 근거·의도를 공유하므로 랜덤 분할을 독립 홀드아웃으로 부르면 안 된다. `leakage_groups.jsonl`은 연결을 찾는 보수적 보조 자료이며, 알려지지 않은 의미적 중복까지 모두 검출했다는 뜻은 아니다. 새 파일의 향후 분할에는 원본 행의 `split_group_id` 대신 이 연결 정보를 함께 사용해야 한다.

법령·행정정보는 저장된 동결 코퍼스에 한정하며 현행성은 재검증하지 않았다. 새로운 사용자 후속 답변, 실제 업무 처리 결과, 검색·응답 성능은 만들지 않았다. 기존 Week 7 후보 캐시는 608문항용이므로 신규 문항의 검색 결과로 재사용하면 안 된다.
