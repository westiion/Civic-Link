# 기존 608문항 A/B/C 비교

작성: 2026-11-13T16:13:14+09:00

**결론: 반복 검색은 필수 근거 확보를 개선했다. Graph 추가의 순개선은 작았고, 내용 표본에서는 C가 가장 높았지만 A와 1문항 차이여서 우위를 확정하지 않는다.**

세 조건이 모두 저장된 문항: **608/608**. 기존 608문항(답변형 488·추가 질문 60·보류 60)을 사용했다. 새 복합 392문항은 제외했다.

## 전체 근거 회수·실행 결과

근거 지표는 기존 검색 평가 대상인 답변형 488문항으로 계산했다. 평균 시간·호출·실행 실패는 전체 608문항 기준이다. 원본 evaluation-608 자동 집계는 근거 주석이 있는 추가 질문·보류 63문항까지 포함한 551문항 지표이며, 아래 488문항 지표와 분모가 다르다. 원본은 변경하지 않고 analysis-488.json에 별도 집계했다.

| 조건 | 최종 입력의 필수 근거 완전회수 | 인용 근거 완전회수 | 평균 시간 | 평균 모델 / 도구 호출 | 응답 실패 |
|---|---:|---:|---:|---:|---:|

| C · 반복 검색 + Graph | 460/488 (94.26%) | 441/488 (90.37%) | 46.6초 | 1.43 / 1.35 | 3 |

근거 완전회수는 지정 근거 묶음을 모두 확보했는지를 뜻하며 답변 정확도와 다르다. B/C는 여러 번 수집한 근거를 사용할 수 있으므로 이 지표를 고정 상위 10개인 Week7 Complete@10과 동일하게 부르지 않는다. 평균 시간에는 공통 첫 검색 시간이 각 조건에 포함되며, 병렬 실행 전체 벽시계 시간과 다르다.

## 가설별 비교

| 비교 | 근거 완전회수 개선 | 퇴보 | 유지 |
|---|---:|---:|---:|
| H1 · A → B: 반복 검색 효과 | 23 | 0 | 465 |
| H2 · B → C: Graph 기능 추가 효과 | 5 | 3 | 480 |

같은 문항에서 개선과 퇴보를 함께 집계했다. Graph 조건의 변화에는 도구 선택과 탐색 경로 변화가 함께 포함된다.

C의 실제 Graph 호출은 전체 608문항 중 13문항에서 총 15회였다. 호출 모드: {'direct': 9, 'traverse': 6}. Graph 후보 제공·도구 선택지 추가 효과와 실제 Graph 조회 효과를 이 실행만으로 완전히 분리하지 못한다.

B→C 근거 개선 5문항 중 실제 Graph를 호출한 문항은 SJ-N-050 한 개였다. 나머지 개선을 Graph 조회가 직접 해결한 결과라고 설명하면 안 된다. 개선·퇴보 문항 ID는 analysis-488.json에 보관했다.

효율성 보조 분석: 전체 문항 평균 시간은 A 35.0초, B 44.7초, C 46.6초였다. 평균 기록된 토큰은 A 12,911개, B 19,726개, C 29,069개였다. C는 B보다 평균 토큰이 약 47% 늘었으나 근거 완전회수는 2/488문항(0.41%p) 증가했다. 따라서 현재 설정에서 Graph의 추가 비용 대비 효과는 제한적이다. 토큰 합계는 응답이 반환된 호출의 usage 기록 기준이며, HTTP 오류 호출의 입력 비용은 포함되지 않는다.

## 내용 평가: 사전 선정한 60문항 표본

질문 유형과 기대 행동으로 층화한 표본이다. 답변형 48·추가 질문 6·보류 6문항을 생성 결과와 관계없이 미리 선정했다. 조건 이름을 숨기고 생성과 같은 Qwen 모델로 사후 판정하므로 독립적인 사람 검증이나 전체 608문항의 정확도로 해석하지 않는다.

| 조건 | 평가된 문항 | 내용 판정 통과율 |
|---|---:|---:|
| A · 한 번 검색 | 60/60 | 75.00% |
| B · 반복 검색 | 60/60 | 71.67% |
| C · 반복 검색 + Graph | 60/60 | 76.67% |

내용 통과는 요구한 행동·필수 내용·사실·근거·인용을 충족하고 근거 없는 주장이 없어야 인정한다. 생성 실행 실패도 실패로 포함했다. 채점 오류 1건은 동일 설정으로 재시도해 해소했으며 생성 응답은 다시 만들거나 교체하지 않았다.

| 기대 행동 | A 통과 | B 통과 | C 통과 |
|---|---:|---:|---:|
| 답변 | 43/48 | 41/48 | 45/48 |
| 추가 질문 | 0/6 | 0/6 | 0/6 |
| 보류·기능 한계 안내 | 2/6 | 2/6 | 1/6 |

A→B 내용 판정은 개선 4·퇴보 6문항, B→C는 개선 5·퇴보 2문항이었다. 추가 질문형 6문항은 모두 필수 확인 기준에 미달한다고 자동 채점됐다. 조건을 먼저 확인하지 않고 일반 안내를 길게 제공하는 사례가 있어 검색과 별도로 응답 행동을 보완해야 한다.

채점 설명도 점검이 필요하다. 예를 들어 C의 SJ-X-050은 답변 말미에 서류 종류를 묻는데, 채점 설명은 이를 묻지 않았다고 기술했다. 신청 방식·위임 여부를 직접 확인하지 않은 문제는 남지만, 자동 판정 설명에 오독이 있어 표본 통과율을 사람 검증 결과로 해석하지 않는다. 표본은 작고 한 문항이 1.67%p에 해당하므로 C의 A 대비 1문항 우위를 확정적인 성능 개선으로 결론내리지 않는다.

## 실행 조건·확인한 한계

- V100 32GB × 4, GPU당 작업자 4개, 생성·임베딩 API 동시 요청 최대 16개.
- 동일 Qwen 생성·임베딩 모델, 동일 코퍼스·색인, BGE float32·입력 1,024토큰·배치 4. temperature 0, thinking 비활성화.
- 같은 질문의 첫 검색을 한 번 계산해 A/B/C에 공유했다. B/C는 모델 최대 8회·도구 최대 6회이며 첫 검색도 포함한다.
- 1,000문항 실행에서 기존 608문항으로 범위를 줄일 때 질문·정답의 동일성을 확인하고, 완료 응답 460개를 해시 검증 후 재사용했다. 원래 실행 설정과 범위 변경 기록을 보존했다.
- 시스템의 기능 한계를 문서 근거로 확인한 항목으로 작성해 근거 ID 검증에 걸린 사례를 발견했다. 실패 결과를 제외하거나 성공으로 교체하지 않았다.
- 실행 실패 6건: 시스템 기능 한계 확인 항목의 근거 ID 누락 4건, 제공되지 않았거나 중복된 근거 ID 검증 실패 1건, Qwen 입력 한도 초과 1건. 도구 자체의 실행 오류는 0건이다.
- W7V2-MS008(C)은 민법 조문 목록 1,192개를 받은 뒤 다음 입력이 664,549자로 증가했다. 종료 후 같은 요청을 한 번 재현해 HTTP 400 응답 본문에서 262,144토큰 문맥 한도 초과를 확인했다. 원실험 결과는 바꾸지 않았다. http400-diagnostic.json에 기록했다.
- 원자료·문항별 결과·호출 이력·근거·설정·평가 JSON/CSV를 함께 보관한다. 개선·퇴보 사례의 본문 검토와 기능 한계 안내 규칙 보완이 후속 과제다.
