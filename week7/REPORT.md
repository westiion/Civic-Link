## 2. 초기 검색 방식 비교와 실패 원인 분석

2.1절은 검색 방식을 처음 비교한 결과다. 2.2·2.3절은 **1,024토큰 기준선**에서 어느 근거를 놓쳤고 후보 보완으로 어디까지 회복했는지 보여준다. 2.4절은 최초 512토큰 평가에서 선정해 원문을 대조한 사례 분석이다.

### 2.1 Hybrid 기준선 및 재정렬 방식 비교

**공통 실험 조건**

- **Hybrid 기준선**

  BM25(단어 기반 검색)와 Dense(임베딩 기반 검색)의 순위를 RRF(결합 상수 60)로 합쳤다. Hybrid 단독 조건에서는 이 순위를 그대로 평가했다.

- **Graph 탐색**

  Hybrid 상위 10개 청크에서 최대 5개 시작점을 골라 2홉까지 탐색했다. Graph 후보를 고르는 경로 점수에는 출발점의 Hybrid 순위가 반영된다. 아래 H3와 coverage는 후보가 정해진 뒤 적용하는 식이다. 특히 coverage는 근거까지의 홉 수와 상위·하위 항목을 잇는 `PART_OF` 관계를 점수에 반영한다.

- **Hybrid+Graph 후보 구성**

  질문마다 Hybrid 상위 100개와 Graph 상위 최대 100개를 모았다. 같은 `chunk_id`는 후보 목록에 한 번만 넣고, 각 검색에서의 순위는 보존했다. 이 절의 Hybrid+Graph 방식은 모두 같은 후보 목록에서 출발한다.

- **평가 대상**

  답변 가능한 488문항에서 최종 상위 10개와 100개를 각각 평가했다. **완전회수**는 필수 근거 묶음을 모두 찾은 문항 수, **Recall**은 문항별로 찾은 묶음 비율의 평균이다. **MRR**은 첫 정답 근거가 얼마나 일찍 등장하는지 보여준다. 여러 근거가 필요한 질문에서는 첫 근거를 일찍 찾아도 완전회수에 실패할 수 있다.

<details>
<summary> H3 점수 산출식 </summary>

```text
R = [1 / (60 + r_H) + 1 / (60 + r_G)] / (2 / 61)
H3 점수 = 0.5 × R + 0.3 × C + 0.2 × Q
```

**순위 기호**
- `r_H` — 후보 청크의 Hybrid 검색 순위
- `r_G` — 후보 청크의 Graph 검색 순위

**점수 항목**
- `R` · 검색 순위 점수 — Hybrid와 Graph의 순위 점수를 합친 값이다. 두 검색에서 모두 1위이면 `R = 1`이고, 한쪽 검색에 후보가 없으면 해당 항은 0으로 계산한다.
- `C` · 후보 본문 일치도 — 질문 단어 중 후보 청크의 제목·본문에 포함된 단어의 비율이다. 전체 청크에서 드물게 등장하는 질문 단어에 더 큰 가중치(IDF)를 준다.
- `Q` · 근거 인용문 일치도 — 각 Graph 경로의 원문 인용문에 `C`와 같은 계산을 적용한 뒤, 가장 높은 값을 사용한다. Graph 후보에 포함되지 않은 청크는 `Q = 0`이다.

</details>

<details>
<summary> coverage 점수 산출식 </summary>

```text
H = 61 / (60 + r_H)
경로별 지원 점수 = C / (1 + 0.12 × hop 수) × 0.25^(PART_OF 관계 수)
G = 경로별 지원 점수 중 최댓값
기본 점수 F = 0.3 × H + 0.5 × C + 0.2 × G
선택 점수 = F / F_max − 0.15 × O
```
**순위·경로 기호**

- `r_H` — 후보 청크의 Hybrid 검색 순위
- `hop 수` — 시작점에서 후보 청크까지 해당 경로를 따라간 간선 수
- `PART_OF 관계 수` — 해당 경로에서 상위·하위 항목을 잇는 `PART_OF` 간선을 지난 횟수

**점수 항목**

- `H` · Hybrid 순위 점수 — Hybrid 검색 1위이면 `H = 1`이고, 순위가 내려갈수록 값이 작아진다. Hybrid 후보에 없으면 `H = 0`이다.
- `C` · 후보 본문 일치도 — H3와 같은 값이다. 질문 단어 중 후보 청크의 제목·본문에 포함된 단어의 비율이며, 드문 단어에 더 큰 가중치(IDF)를 준다.
- `G` · Graph 경로 지원 점수 — `C`를 기준으로 경로가 길수록 점수를 낮추고, `PART_OF` 관계를 한 번 지날 때마다 0.25를 곱한다. 여러 경로가 같은 청크에 도달하면 가장 높은 경로 점수를 사용한다. Graph 후보에 없으면 `G = 0`이다.
- `F` · 후보 기본 점수 — `H`, `C`, `G`에 각각 30%, 50%, 20%의 가중치를 적용한 합이다.

**상위 10개 선택**

`F_max`는 전체 후보 중 가장 높은 기본 점수다. `O`는 이미 선택한 청크들과의 최대 겹침률이다. 같은 문서에서 겹친 글자 수를 두 청크 중 짧은 쪽의 글자 수로 나누며, 서로 다른 문서라면 겹침률은 0이다.

첫 번째 청크는 `O = 0`이므로 기본 점수가 가장 높은 후보를 고른다. 이후에는 청크를 하나 고를 때마다 겹침률을 다시 계산해 선택 점수가 가장 높은 후보를 고른다. 이렇게 10개를 선택하고, 나머지 후보는 기본 점수순으로 정렬한다.

**계수 선택 기준**

가중치 `0.3 / 0.5 / 0.2`와 중복 감점 계수 `0.15`는 개발 구간에서 여러 조합을 비교해 선택했다. 완전회수@10을 우선하고, 동점일 때 Recall@10과 MRR@100을 차례로 비교했다. 경로 길이 계수 `0.12`와 `PART_OF` 계수 `0.25`는 경로 점수 계산에 사용한 고정값이다.

</details>

<details>
<summary> BGE 재정렬 방식 </summary>

BGE는 질문과 후보 청크의 제목·본문을 한 쌍으로 읽고, 해당 청크가 질문과 얼마나 관련 있는지 점수를 매기는 재정렬 모델이다. 이번 실험에서는 `BAAI/bge-reranker-v2-m3`로 Hybrid+Graph가 확보한 후보 전체를 채점하고, 점수가 높은 순서로 정렬했다.

- **BGE 직접 정렬(4번)** — BGE 원점수가 같으면 `chunk_id` 오름차순으로 순서를 정한다.
- **H3 또는 coverage → BGE(5·6번)** — 같은 후보 전체를 BGE 점수순으로 정렬하되, 동점일 때만 H3 또는 coverage가 매긴 순서를 따른다.

</details>

#### 후속 실험의 비교 기준 선정

- **경로를 반영한 수식의 효과.** 같은 후보에서 H3를 coverage로 바꾸자 완전회수@10은 **391→411문항**, @100은 **481→475문항**이 됐다. 최종 10개에서는 개선됐지만, 수식의 여러 요소를 함께 바꾼 결과여서 홉 가중치 하나의 효과로 분리할 수는 없다.
- **Graph가 추가한 후보의 효과.** 재정렬을 BGE로 고정하면 Hybrid 후보 100개에서는 **434/488**, Graph 후보를 합치면 **437/488**이었다. 새로 성공한 문항은 3개, 기존 성공을 잃은 문항은 0개였다. [같은 BGE로 비교한 결과](EXPERIMENT2.md#추가-조건-무엇이-기여했나)
- **실패 분석 기준.** 4·5·6번은 같은 후보에 같은 BGE 원점수를 쓰고, 5·6번에서 앞선 식은 동점 순서에만 영향을 준다. 세 방식 모두 완전회수@10이 **437/488**이어서, 각 근거가 어디서 밀렸는지 원점수로 추적할 수 있는 **4번**을 기준으로 삼았다.

### 2.2 입력 길이 보정과 실패 사례 분석

- **왜 1,024토큰으로 늘렸나?** 최초 순위 탈락 44문항 중 6문항은 답에 필요한 문장이 512토큰에서 잘렸다. 같은 후보를 1,024토큰으로 다시 채점하자 **6문항 중 5문항**에서 필요한 근거가 모두 상위 10개에 들었다.
- **전체 488문항에서는 어떻게 달라졌나?** 기존 후보를 1,024토큰으로 평가하자 512토큰에서 실패한 **6문항이 새로 성공**했고, 성공했던 **다른 6문항은 실패**했다. 완전회수@10은 두 조건 모두 **437/488**이었다.
- **1,024토큰에서 실패한 51문항** 중 **7문항**은 필수 근거가 후보에서 빠졌고, **44문항**은 근거가 모두 100위 안에 있어도 10위 안에 모이지 않았다. 2.3절에서는 후보 누락 7문항을 살펴본다.
