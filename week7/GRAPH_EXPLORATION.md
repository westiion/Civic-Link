# 가중치 그래프 개선 탐색 · 2026-11-03

현재 그래프의 약점은 가중치 하나보다 **시작점 선택, 막힌 탐색 방향, 관련도 신호의 중복 사용**에 있다. 같은 후보에서 그래프 점수를 작게 보태는 조건은 유망하지만, 그래프 비중이나 후보 수를 크게 늘리는 조건은 회귀도 일으켰다. 운영 기본값은 변경하지 않았다.

기준 체크아웃은 `92bbd31`. 기존 입력·결과·모델을 보존하고 새 실험 스크립트와 결과만 추가했다. 고정 후보 점수 비교 54조건과 시작점·탐색 7조건을 평가했다. 마지막으로 새 그래프 후보를 기존 후보에 **추가**하는 조건을 별도로 평가했다.

## 평가 범위

- 전체 608문항 중 answer 488문항의 필수 근거 묶음 회수를 평가한다. clarify·abstain 120문항은 검색 성적에서 제외한다.
- Complete@10은 필요한 근거를 모두 회수한 문항 수, Recall@10은 문항별 근거 묶음 회수율 평균, MRR@10은 첫 허용 근거 순위 역수의 평균이다.
- 고정 후보는 기존 Hybrid100 ∪ Graph≤100, 전체 68,430쌍이다. 모든 고정 후보 실험에서 동일한 후보와 BGE 원점수를 사용했다.
- BGE는 `BAAI/bge-reranker-v2-m3`, revision `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`, **512토큰** 기준이다. 이후의 1,024토큰 실험과 혼합하지 않았다.
- 608문항 모두 `synthetic=true`, `human_verified=false`, `independent_gold=false`, `independent_holdout=false`, `eligible_for_official_metrics=false`다. 아래 수치를 실제 민원 정확도나 독립 검증 성적으로 해석하지 않는다. 생성 답변은 평가하지 않았다.

## 무엇이 성능을 제한하나

### 1. 현재 가중치는 학습한 엣지 중요도가 아니다

[현재 탐색 코드](../src/civic_link/retrieval/hybrid_graph.py)는 다음과 같은 휴리스틱을 쓴다.

```text
경로 점수 = (1 / 시작점의 Hybrid 순위)
          × (0.45 + 질문·청크 IDF 단어 겹침)
          / (1 + 0.12 × hop)
          × 조건 근거 보정(0.95 또는 1)
```

가장 높은 경로 하나로 Graph 순위를 정하고, Hybrid 순위와 RRF로 합친다. H3에서는 여기에 청크·인용문 단어 겹침을 다시 더한다. **Hybrid에서 높은 시작점의 근거가 Graph와 결합 단계에서도 재차 유리해진다.** 또한 질문 단어와 전혀 겹치지 않아도 0.45가 남고, 순위로 바꾸면 근거 강도의 차이가 약해진다.

현재 coverage 수식은 이 문제 일부를 완화해 391→411문항으로 개선했지만, BGE 직접 정렬 437문항에는 미치지 못한다. 관계 경로가 존재한다는 사실은 그 청크가 질문에 대한 답을 포함한다는 보장이 아니다.

### 2. 법령 노드 64개가 모두 탐색의 막다른 지점이다

노드는 6,182개, 엣지는 9,437개다. 엣지 구성은 `PART_OF` 6,046개, `REFERENCES` 3,090개, `GROUNDED_BY` 155개, `REQUIRES` 84개, `HANDLED_BY` 62개다.

`Article → Law`만 있고 반대 방향의 탐색은 없다. Law 64개 모두 out-degree가 0이다. 따라서 `이미 찾은 조문 → 소속 법령 → 같은 법령의 관련 조문` 경로가 열리지 않는다. 독립 Graph는 2→3-hop을 늘려도 Complete@10이 176으로 같고 전체 후보의 완전회수 상한도 192로 같다. 단순히 hop만 늘리는 방법의 기대 효과가 작다.

### 3. Graph 단독은 시작점·연결 범위에서 먼저 실패한다

| 조건 | Complete@10 | 전체 후보의 완전회수 상한 |
|---|---:|---:|
| 독립 명칭 매칭 Graph · 2-hop | 176/488 | 192/488 |
| Hybrid 시작점 기반 Graph 분기 | 316/488 | 366/488 |
| Hybrid ∪ Graph 전체 후보 | 최종 정렬에 따라 다름 | 481/488 |

독립 Graph는 608문항 중 53문항에서 시작점이 없다. 전체 그래프의 모든 evidence record를 합쳐도 허용 근거가 덮이지 않는 answer 문항이 6개 있다. 이 중에는 제출 서류와 담당 기관 안내의 근거도 있다. 연결 데이터의 보완과 검색 알고리즘의 개선을 구분해야 한다.

Hybrid 시작점은 처음 10개 청크의 연결 노드를 ID 순으로 고르며 시작점 최대 5개, 청크당 최대 2개다. 551/608문항에서 시작점 한도 때문에 배제된 노드가 있었다. 다만 아래 실험에서 단순히 시작점을 더 주거나 명칭 점수로 바꾸는 방법은 최종 순위를 안정적으로 개선하지 못했다.

## 새 후보를 BGE로 평가하는 추가 실험

기존 후보·원점수를 모두 유지하고, 시작점 확대와 역방향 5개 탐색으로 새로 찾은 후보만 추가했다. 8,799개 새 질문·청크 쌍과 질문별 기존 BGE 10·11위 대조군 1,216쌍을 기존 로컬 모델로 채점했다. 원래와 같은 revision·패키지·512토큰·MPS float16·batch32·SDPA를 사용했다. 원격 API·다운로드는 비활성화했다.

[추가 실험 결과](results/graph_exploration_20261103/expansion/summary.json)는 다음과 같다.

|---|---:|---:|---:|---:|
| 기존 BGE | 437/488 | 93.26% | 0.8336 | 481 / 481 |
| 시작점 확장 후보를 추가 | 437/488 | 93.26% | 0.8336 | 482 / 482 |

후보 크기는 질문당 평균 112.55→127.02개, 최종 범위는 101~191개다. 새 쌍은 기존 채점량의 약 12.86%이며, 대조군까지 포함한 10,015쌍의 로컬 추론에 약 224.3초가 걸렸다. 준비·전체 서비스 지연을 포함한 시간이 아니다. 새 입력 중 2,847쌍은 512토큰에서 잘렸다.

`SJ-B-011`의 제20조 근거는 후보 밖에서 **11위**, `SJ-N-052`의 제33조 근거는 **20위**로 들어왔다. 두 누락을 해결했지만 top10 회복에는 이르지 못했다. 608문항 중 66문항의 top10 후보 집합이 바뀌었으며, answer 488문항에서 Complete·Recall·MRR은 모두 동일했다. **후보 상한의 상승을 답변이나 top10 성능 개선으로 보고하지 않는다.**

기존 10·11위 대조군 1,216개 중 923개는 원점수가 정확히 같았다. 절대 차이 평균 0.000853, 95백분위 0.003906, 최대 0.010742였다. 기존 점수는 바꾸지 않았다. 새 후보 점수에 일괄 ±0.05·±0.1을 더하는 민감도 확인에서도 Complete@10은 437, @100은 483이었다. 이 민감도 확인은 오차 한계의 수학적 보장은 아니다.

새 후보가 있는 경우 최종 top10은 다시 경쟁하므로 **기존 후보를 보존해도 성공 문항의 보존까지 보장되지는 않는다.** 이번 조건에서는 성공 획득·상실이 각각 0이었다. 확장 정책과 위의 logit 보정 정책을 결합한 실험은 수행하지 않았으므로 효과를 합산하지 않는다.

## 적용 우선순위

1. **작은 logit 보정부터 후속 검증한다.** 시작점 순위를 제거하거나 coverage 지원 점수를 쓰는 442문항 조건이 Complete와 MRR의 균형이 더 좋았다. RRF 15%의 최고 수치만 보고 기본값을 바꾸지 않는다. 7개 회복 사례와 2개 회귀 사례를 함께 검수한다.
2. **후보 확장과 최종 정렬을 분리한다.** 이번의 무조건적 확장은 추가 추론을 쓰고도 top10을 개선하지 못해 기본값으로 채택하지 않는다. 역방향 5개 탐색은 누락 근거를 회복하는 수단으로 보존하고, 질문의 조문·조건 요구와 결합해 필요한 경우에만 후보를 추가하는 후속 조건을 검증한다. 관련 조문을 한꺼번에 모두 넣는 방향은 이번 결과가 지지하지 않는다.
3. **시작점은 별칭 단어 겹침보다 질문과 근거 문맥의 관련도로 고른다.** Hybrid 또는 BGE 상위 청크를 이용하고, 비교 질문의 서비스별 시작점을 확보하는 방식을 별도 실험한다. 이번의 간단한 명칭 재선택은 실패했으므로 그 자체는 적용하지 않는다.
4. **다음 구조 개선은 청크·사실과 조건 연결이다.** 법령 소속뿐 아니라 신청자·서류·예외·처리기관과 실제 근거 청크를 명시적으로 연결한다. 현재 누락된 제출 서류·담당 기관 evidence도 함께 보완한다. 원문 근거 없이 법적 관계를 만들어 넣지는 않는다.
5. **PPR은 청크 문맥을 함께 넣는 후속 후보로 둔다.** [HippoRAG 2](https://arxiv.org/html/2502.14802v2)는 passage 노드, 질문과 triple의 연결, 관련 triple 필터링을 PPR과 함께 사용한다. 이를 근거로 현재 그래프에 PPR 하나만 붙이면 개선된다고 보지는 않는다. [KG²RAG](https://arxiv.org/abs/2502.06864)도 의미 검색으로 시작 청크를 찾은 뒤 KG 확장·조직화를 수행한다. 우리 데이터에 맞는 적용 효과는 아직 측정하지 않았다.

다음 정책 선택에는 새 실제 질문과 사람이 검수한 근거가 필요하다. 현재 데이터의 review 구간도 이미 반복 분석한 개발 자료이므로 독립 검증으로 이름을 바꿔 사용하지 않는다.
